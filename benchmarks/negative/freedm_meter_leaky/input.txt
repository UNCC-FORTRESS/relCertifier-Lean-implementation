# freedm_meter_leaky: the deterministic controller batI of the FREEDM case study, expected
# DECLINED (the information leak). NOT part of the certified suite: a negative exhibit.
# scenario: information-flow
#
# Same model as benchmarks/suite_v2/freedm_meter (see its header for the source and the form),
# with batI on both sides (Bohrer and Platzer, LICS 2018, Figure 2): the battery serves the
# cycle whenever it can, "(n <= 0 and B < Bmax) or (n > 0 and B > 0)" for the net demand
# n = d - r, and the grid serves it otherwise, i.e. a surplus meets a full battery or a demand
# meets an empty one. In the sampled form "can" means one period: a surplus of 1 charges only
# from B <= 9, a demand n discharges only from B >= n; the grid takes the other cycles. A grid
# cycle with a nonzero net demand therefore reveals through the meter that the battery is full
# (or empty): no run from another level keeps the meters equal, and the tool DECLINES (the
# source's Proposition 10; there the draw itself is observed, so a zero-net grid cycle leaks
# too). A DECLINE is not a proof
# of insecurity (the certifier is sound, not complete); the source proves the leak by exhibiting
# the two runs.
