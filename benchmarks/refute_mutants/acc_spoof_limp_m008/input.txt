# acc_spoof_limp: spoofed cruise control with a fault-latched limp-home mode, against a reference
# with driver-selectable set speeds.
# scenario: sensor-attack
# mechanisms: M B P D I (multi-step covers; branching joint steps; pruned DISENGAGE edges;
#   mode-dependent rows; checked cuts, matrix codes M2 M3 M4 M5 M6)
#
# System. Speed v (m/s), time s; one car, speed loop of gain 0.5 /s (speed-loop form, no lag).
#   Left (deployed, attacked): the fused speed signal is spoofed to read 25 % high (1.25 v), so
#     CRUISE v' = 0.5 (30 - 1.25 v) = 0.625 (24 - v): the car settles at 24 m/s. Its plausibility
#     monitor compares the fused speed with the wheel-speed sensor; when it flags the mismatch the
#     controller LATCHES a limp-home mode until the next ignition cycle: LIMP v' = 0.3 (22 - v)
#     (the loop reads the unspoofed wheel speed, set speed 22 m/s = 80 km/h, soft gain 0.3 /s).
#     CRUISE -> LIMP may happen at any sample; there is no way back.
#   Right (reference): the unspoofed controller; the driver selects ECO 27, NORMAL 30 or SPORT
#     33 m/s at any time (gain 0.5 /s; NORMAL <-> ECO / SPORT), and below the 20 m/s ACC floor
#     every mode hands back to the driver: DISENGAGE v' = -0.5 v, latched.
# One cause: the spoof (the limp-home latch is the deployed's own response to it).
#
# Guards. CRUISE and the reference's three set-speed modes engage at 20 <= v < 40 (the ACC
# floor); LIMP is entered between 20 and 30 m/s (the monitor latches only while the ACC is
# engaged, at or below the nominal set speed). DISENGAGE v < 20. The right guards cover
# [0, 40); v = 40 (the top of the domain) is in no right guard, and no right run reaches it
# (every mode decelerates there). Physical domain 0 <= v <= 40 m/s on both sides (the vehicle's
# speed range on this road class); every left mode has a satisfiable start (v_L = v_R).
#
# Property (mode-dependent rows).
#   Requirement, both modes: v_L <= v_R, the spoofed car is never faster than the reference
#     (constant 0).
#   Attack-impact bound, per mode: v_R <= v_L + 9 (CRUISE) and v_R <= v_L + 12 (LIMP), how far the
#     spoofed car may fall behind the reference. This bound has no external requirement: the file
#     CERTIFIES with v_L <= v_R alone in both modes (rows then identical, no D). Tightest
#     (bisection to 0.01): CRUISE 6.00 (5.99 declines, LIMP at 12); LIMP 9.00 with CRUISE at 9
#     (the handoff needs LIMP's slack >= CRUISE's) and 8.80 with CRUISE at 6 (8.79 declines). The
#     latched limp loop settles lower and slower, so the bound is looser in LIMP.
# The handoff CRUISE -> LIMP is a loosening (--handoff 3/3 unsat, non-vacuous); LIMP is latched,
# so no tightening switch exists. Not implied by the domains.
#
# Why pruning is needed (P). Every reference mode declares DISENGAGE below the 20 m/s floor; each
# loop accelerates at the floor and is entered above it, so NORMAL, ECO, SPORT -> DISENGAGE are
# pruned by non-connection certificates. v_L >= 20 and v_L <= v_R exclude DISENGAGE as a start.
# Without pruning (RELCERT_NO_PRUNE=1) the joint steps must also cover DISENGAGE and the file
# DECLINES; the committed choice does not replace pruning here.
# Branching (B). In both windows the cover from NORMAL takes joint steps whose retained
# successors ECO and SPORT both cover (branch 2).
# Mode facts (I). The guard conjuncts of every mode (the engagement bands, e.g. LIMP's
# 20 <= v <= 30, which the limp loop keeps) are kept as checked cuts; with RELCERT_NO_CUT=1 every
# LIMP pairing fails at every lambda: DECLINED.
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated): CERTIFIED; CERTIFIED under RELCERT_SYNC=1,
# RELCERT_NO_CHOICE=1, without RELCERT_IMPLIED_CUT, NO_IMPLIED_CUT, NO_LINEAR_CUT and the
# operating region; DECLINED under RELCERT_NO_PRUNE=1, NO_PRUNE+NO_CHOICE, SYNC+NO_CHOICE and
# RELCERT_NO_CUT=1. Covers: CRUISE at lambda = 5/4 (the spoofed loop is 1.25 times faster),
# budget 3; LIMP at lambda = 1, budget 2; admissible starts NORMAL, ECO, SPORT. RELCERT_SYNC=1
# certifies (lambda 1 suffices), so the stretch is used but not needed (no S). Units m/s, s.
[problem]
name = acc_spoof_limp
max_depth = 8
lambda_min = 1.0
lambda_max = 6.0
bound_T = 4.0
[Lsys]
state_vars = [v]
epsilon = 2.0
[Lsys.mode.CRUISE]
ode = v' = smt2:(* 0.5 (- 30.0 (* 1.25 v)));
guard = v >= 20.0 and v < 40.0
evolve = v >= 0.0 and v <= 40.0
next = [CRUISE, LIMP]
[Lsys.mode.LIMP]
ode = v' = smt2:(* 0.3 (- 22.0 v));
guard = v >= 20.0 and v <= 30.0
evolve = v >= 0.0 and v <= 40.0
next = [LIMP]
[Rsys]
state_vars = [v]
epsilon = 1.0
[Rsys.mode.NORMAL]
ode = v' = smt2:(* 0.5 (- 30.0 v));
guard = v >= 20.0 and v < 40.0
evolve = v >= 0.0 and v <= 40.0
next = [NORMAL, ECO, SPORT, DISENGAGE]
[Rsys.mode.ECO]
ode = v' = smt2:(* 0.5 (- 27.0 v));
guard = v >= 20.0 and v < 40.0
evolve = v >= 0.0 and v <= 40.0
next = [ECO, NORMAL, DISENGAGE]
[Rsys.mode.SPORT]
ode = v' = smt2:(* 0.5 (- 33.0 v));
guard = v >= 20.0 and v < 40.0
evolve = v >= 0.0 and v <= 40.0
next = [SPORT, NORMAL, DISENGAGE]
[Rsys.mode.DISENGAGE]
ode = v' = smt2:(* -0.5 v);
guard = v < 20.0
evolve = v >= 0.0 and v <= 40.0
next = [DISENGAGE]
[relational_invariant]
CRUISE = smt2:(and (<= L_v R_v) (<= R_v (+ L_v 9.0)))
LIMP = smt2:(and (<= L_v R_v) (>= R_v (+ L_v 12.0)))
