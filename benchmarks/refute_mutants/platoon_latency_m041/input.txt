# platoon_latency: a CACC follower whose V2V feed-forward (the predecessor's acceleration) arrives
# late, against the design follower with an ideal (zero-latency) link.
# scenario: degraded-network
# mechanisms: none (a tolerance claim: lambda 1, one segment per window, nothing pruned, no cut
#   load-bearing, one row set; CACC_UP and CACC_DN carry the same row, so no D; CERTIFIED under
#   every counter-run, letters measured 2026-10-29: none). Round-4 fix (2026-10-29): the AEB
#   fallback mode is removed from both sides. It was reachable only as a start (the CACC operating
#   range is forward invariant on both sides, see Domains), so its D letter was the rows differing
#   on a mode no CACC run enters (with the AEB removed the file certified with no letter). No
#   physical trigger keeps an AEB pairing (see "Why no AEB" below): letters D -> none.
#
# Shared platoon model (the same CACC, operating range and domain as platoon_linkloss and
# platoon_profiles). A lead vehicle cruises at the platoon reference speed v_ref = 25 m/s
# (90 km/h). Per link (follower behind its predecessor): the gap g (m, bumper to bumper) and the
# range rate r = v_pred - v (m/s, positive = opening), g' = r. Units m, m/s, s.
# Spacing policy (constant time gap): standstill distance d0 = 5 m. CACC: time gap h_c = 0.6 s on
#   the V2V-broadcast reference speed, desired gap d0 + h_c v_ref = 20 m.
# CACC (V2V predecessor-acceleration feed-forward u_ff): a = u_ff + kp (g - 20) + kd r with
#   kp = 0.125 /s^2, kd = 0.75 /s: closed-loop poles 0.25 and 0.5 /s (over-damped). With an ideal
#   link u_ff = a_pred and r' = a_pred - a = -kp (g - 20) - kd r.
# CACC operating range (the engagement spec, the same on both sides): |r| <= 10 (rated closing
#   rate) and 5 <= g + 2 r <= 60 (time to reach the standstill distance at the current closing
#   rate at least 2 s, (g - d0) + 2 r >= 0, and the gap projected 2 s ahead inside the 60 m radar
#   range gate).
# Control period 0.1 s on both sides (10 Hz V2V messages, the ETSI CAM / SAE BSM rate).
# Domain per link (one domain, both sides, every mode): 0 <= g <= 60 m (radar range gate),
#   |r| <= 10 m/s (rated closing rate), |e| <= 20 m/s^2 (the difference of two accelerations each
#   within the 1 g tyre-road limit of 10 m/s^2, as acc_tune_lag's acceleration box).
#
# The cause: V2V latency. The deployed follower's feed-forward is the predecessor's acceleration
# tau = 0.2 s old: the newest message is up to one 0.1 s control period old when it is used, plus
# the 0.1 s end-to-end latency budget of V2V safety messages, so the follower acts on the
# predecessor's acceleration two control periods late. The predecessor's jerk is bounded by
# J = 2.5 m/s^3 (the ISO 15622 ACC jerk limit above 20 m/s, assumed here as a pointwise bound on
# the predecessor's automated longitudinal control). The delayed feed-forward is modeled by its
# first-order lag (time constant tau, u_ff' = (a_pred - u_ff) / tau, the Pade (0,1) model of the
# delay). Its error e = a_pred - u_ff (m/s^2) obeys e' = j_pred - e / tau and enters the loop as
# r' = e - kp (g - 20) - kd r. Like the pure delay's error a_pred(t) - a_pred(t - tau), it is
# bounded by W = J tau = 0.5 m/s^2.
# Left (deployed follower, state g, r, e): CACC_UP and CACC_DN are the same CACC while the
#   predecessor's acceleration rises (j_pred = +J) or falls (j_pred = -J) at the jerk limit; the
#   predecessor may switch between them at every control instant (next [CACC_UP, CACC_DN]). The
#   field is affine in j_pred, so every face condition that holds at both extremes holds for every
#   jerk in between. Guards: the operating range (same as the design's), any e.
# Right (design follower, state g, r, e): the same CACC with an ideal link, next [CACC]. The design
#   has no feed-forward lag: its e is an inert coordinate, frozen (e' = 0), that never enters g, r.
# One cause: the latency (the lag and its error e). Same plant, gains, operating range and control
# period on both sides; lambda_min = lambda_max = 1 (same time). The predecessor is the same on
# both sides; the relative coordinates make the design's motion independent of it.
#
# Property (Delta = L - R; rows CACC_UP and CACC_DN identical).
#   |Delta g| <= 4. Requirement (the latency's spacing-error allowance): a feed-forward error held
#     at its bound W shifts the CACC's equilibrium gap by W / kp = J tau / kp = 2.5 x 0.2 / 0.125
#     = 4 m (0.16 s of time gap at v_ref); the requirement is that the transient never exceeds
#     this static allowance, for every predecessor manoeuvre within the jerk limit. Tight: 4.00
#     certifies, 3.99 declines (the loop is over-damped, so the error never overshoots its static
#     value).
#   |Delta r + 0.25 Delta g| <= 1 and |Delta r + 0.5 Delta g| <= 2 (derived, 2 W and 4 W): the
#     forms Q_rho = Delta r + rho Delta g obey Q_0.25' = -0.5 Q_0.25 + e and
#     Q_0.5' = -0.25 Q_0.5 + e, and Delta g' = Q_0.25 - 0.25 Delta g; both tight (0.99, 1.99
#     decline).
#   g_L >= 5 and g_L + 2 r_L >= 5: collision freedom of the deployed (gap at least d0) and its TTC
#     to d0 at least 2 s (the latency never pushes the deployed out of the operating range).
#     d/dt (g + 2 r) = -0.25 (g + 2 r - 20) + 2 e, so the TTC floor is kept iff
#     W <= 0.25 x 15 / 2 = 1.875 m/s^2 (tau <= 0.75 s at J = 2.5). 5.00 is tight for the gap
#     floor (5.01 declines: it is kept only through the TTC floor); TTC floors up to
#     20 - 8 W = 16 m certify (16.01 declines): the latency costs the deployed 4 m of projected
#     stop gap.
#   |e_L| <= W = 0.5 m/s^2 (stated strengthening, the feed-forward error stays within J tau): the
#     delayed feed-forward never errs by more than the jerk limit times the latency. Inductive
#     (e' = +-J - e / tau points inward at e = +-W) and tight (0.49 declines): the deployed's lead
#     over the design is driven by e, so the gap rows above need this bound (the domain audit of
#     2026-10-29 moved it from the deployed's evolve domain, where it was a reachable-set band,
#     into the claim, where the tool checks it).
#   (Round 4 dropped the strengthening 5 <= g_R + 2 r_R <= 60 on the design: it was needed only to
#   keep the design's AEB out of the admissible starts; the design's guard carries the same
#   operating range, and without it the file certifies under every counter-run, RELCERT_OPREGION=1
#   included.)
#
# The bound grows with the latency (re-measured 2026-10-29 on the one domain, without the AEB, every
# other constant at its derived value 2 W, 4 W, W): tightest |Delta g| = 2.00 / 4.00 / 6.00 /
# 10.00 / 15.00 m at tau = 0.1 / 0.2 / 0.3 / 0.5 / 0.75 s (each 0.01 below declines), i.e.
# J tau / kp. Without latency (J tau = 0, e = 0) the exact claim (every Delta = 0) CERTIFIES
# (measured before the round-4 fix). At tau = 0.8 s (W = 2) the file DECLINES: the deployed's TTC
# floor fails (d/dt (g + 2 r) = 3.75 + 2 e < 0 on the face g + 2 r = 5 once e < -1.875), so the
# deployed can leave the operating range while the design cannot.
#
# Why no AEB (round-4 analysis, 2026-10-29). Earlier files carried the radar AEB (trigger
# g + 2 r < 5, matching law r' = -0.5 r, latched) on both sides, with exact AEB rows. The CACC
# operating range is forward invariant on both sides (TTC floor above; g + 2 r <= 60 since the CACC
# drives g + 2 r toward 20 +- 8 W; the |r| <= 10 faces hold below 70 m), so no CACC run triggers
# the AEB. A run reaches it only under a disturbance the CACC cannot cancel, a predecessor braking
# beyond the feed-forward's authority. Modeled as a lead-braking mode on both sides (feed-forward
# clipped at 3.5 m/s^2, the ISO 15622 ACC deceleration limit, predecessor at 6 m/s^2: the 2.5 m/s^2
# excess drives g + 2 r toward 0, so the AEB fires after about 5.5 s from the 20 m gap), the file
# DECLINES (two scratch variants, measured 2026-10-29): the design's
# lead-braking mode has the CACC's guard, so the rows (keyed by the deployed's mode) admit a
# design braking against a deployed in CACC and the segment (CACC_UP_L, LB_R) fails, also with
# the design's AEB trigger widened to g + 2 r < 9. Beyond that, the two AEBs fire at different
# control instants (the projected stop gaps differ by up to 2 |Q_0.5| = 4 m, either sign); once
# the predecessor releases, a latched AEB on one side faces a recovering CACC on the other, and no
# bounded spacing row holds. An AEB fired by a shared event (both at once) with the matching law
# keeps the CACC rows (Delta g, the Q forms and the floors are invariant under r' = -0.5 r), so
# the uniform row would certify and give no D. Hence the AEB is removed and D is lost.
#
# Domains. One domain on both sides and every mode: 0 <= g <= 60, |r| <= 10, |e| <= 20 m/s^2
# (physical, as above; the domain audit of 2026-10-29 replaced the deployed's earlier
# |e| <= W = 0.5, the error band the jerk limit makes reachable, which the claim stood on: widened
# by 5 % the file declined; the band is now the stated row above). Not load-bearing: every bound
# widened by 20 % of its range CERTIFIES (measured 2026-10-29 on this file).
# Coverage of the right guard: CACC covers every domain state with |r| <= 10 and
# 5 <= g + 2 r <= 60; the other domain states are in no right guard and no run reaches them (the
# guard is forward invariant). Every left mode has a satisfiable start (g_L = g_R = 20, r = 0,
# any |e_L| <= 0.5).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, measured 2026-10-29 on this file): CERTIFIED
# (about 0.5 s: 487 ms in the letters run, 0.6 s in the ablation run; the pre-fix file with the
# AEB measured 1.2 s, not the 2.0 s stated before); CERTIFIED under every counter-run
# (RELCERT_SYNC=1, RELCERT_NO_CHOICE=1, SYNC+NO_CHOICE, RELCERT_NO_PRUNE=1, NO_PRUNE+NO_CHOICE,
# RELCERT_NO_REPO=1, RELCERT_NO_CUT=1, RELCERT_NO_IMPLIED_CUT=1, RELCERT_NO_LINEAR_CUT=1, without
# RELCERT_IMPLIED_CUT, RELCERT_OPREGION=1, RELCERT_NO_PAIR_STRETCH=1), RELCERT_WELLFORMED_STRICT=1
# and with every evolve bound widened by 20 % of its range. Tight values as stated above
# (|Delta g| 4.00, 3.99 declines; the Q rows 1 and 2, 0.99 and 1.99 decline; g_L >= 5.00, 5.01
# declines; TTC floor 16, 16.01 declines; the e row 0.50, 0.49 declines). Cover: every left mode
# at lambda 1, budget 1 (single segment), admissible start [CACC], nothing pruned. --handoff 4/4
# passed (vacuous: one row set). relcert --wellformed: CACC ok (invariant), 0 UNKNOWN, 0 BLOCKING.
# One-domain check passes. Letters (scripts/suite_v2_letters.py through letters.sh): D before the
# round-4 fix, none after.
#
[problem]
name = platoon_latency
max_depth = 8
lambda_min = 1.0
lambda_max = 1.0
bound_T = 4.0
[Lsys]
state_vars = [g, r, e]
epsilon = 0.1
[Lsys.mode.CACC_UP]
ode = g' = smt2:r; r' = smt2:(- (- e (* 0.125 (- g 20.0))) (* 0.75 r)); e' = smt2:(- 2.5 (* 5.0 e));
guard = r >= -10.0 and r <= 10.0 and g + 2.0 * r >= 5.0 and g + 2.0 * r <= 60.0
evolve = g >= 0.0 and g <= 60.0 and r >= -10.0 and r <= 10.0 and e >= -20.0 and e <= 20.0
next = [CACC_UP, CACC_DN]
[Lsys.mode.CACC_DN]
ode = g' = smt2:r; r' = smt2:(- (- e (* 0.125 (- g 20.0))) (* 0.75 r)); e' = smt2:(- (- 0.0 2.5) (* 5.0 e));
guard = r >= -10.0 and r <= 10.0 and g + 2.0 * r >= 5.0 and g + 2.0 * r <= 60.0
evolve = g >= 0.0 and g <= 60.0 and r >= -10.0 and r <= 10.0 and e >= -20.0 and e <= 20.0
next = [CACC_UP, CACC_DN]
[Rsys]
state_vars = [g, r, e]
epsilon = 0.1
[Rsys.mode.CACC]
ode = g' = smt2:r; r' = smt2:(- (* -0.125 (- g 20.0)) (* 0.75 r)); e' = smt2:0;
guard = r >= -10.0 and r <= 10.0 and g + 2.0 * r >= 5.0 and g + 2.0 * r <= 60.0
evolve = g >= 0.0 and g <= 60.0 and r >= -10.0 and r <= 10.0 and e >= -20.0 and e <= 20.0
next = [CACC]
[relational_invariant]
CACC_UP = smt2:(and (>= (+ (- L_r R_r) (* 0.25 (- L_g R_g))) (- 0.0 1.0)) (<= (+ (- L_r R_r) (* 0.25 (- L_g R_g))) 1.0) (>= (+ (- L_r R_r) (* 0.5 (- L_g R_g))) (- 0.0 2.0)) (<= (+ (- L_r R_r) (* 0.5 (- L_g R_g))) 2.0) (>= (- L_g R_g) (- 0.0 4.0)) (<= (- L_g R_g) 4.0) (>= L_g 5.0) (>= (+ L_g (* 2.0 L_r)) 5.0) (>= R_e (- 0.0 0.5)) (<= L_e 0.5))
CACC_DN = smt2:(and (>= (+ (- L_r R_r) (* 0.25 (- L_g R_g))) (- 0.0 1.0)) (<= (+ (- L_r R_r) (* 0.25 (- L_g R_g))) 1.0) (>= (+ (- L_r R_r) (* 0.5 (- L_g R_g))) (- 0.0 2.0)) (<= (+ (- L_r R_r) (* 0.5 (- L_g R_g))) 2.0) (>= (- L_g R_g) (- 0.0 4.0)) (<= (- L_g R_g) 4.0) (>= L_g 5.0) (>= (+ L_g (* 2.0 L_r)) 5.0) (>= R_e (- 0.0 0.5)) (<= L_e 0.5))
