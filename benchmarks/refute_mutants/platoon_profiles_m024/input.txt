# platoon_profiles: a CACC follower driven in the SPORT profile (the CACC at 1.2 times its
# bandwidth) against the design follower verified in the NORMAL profile; the SPORT follower's
# gap and closing rate are the NORMAL follower's re-timed by the bandwidth ratio 6/5, and the
# AEB is the same function at real time.
# scenario: controller-refinement
# mechanisms: S M D (time stretch, lambda = 6/5 for the SPORT pairing and 1 for the AEB pairing,
#   RELCERT_SYNC=1 declines, matrix code M1; multi-cycle matching, budget ceil(1.2 x 0.1 / 0.1) = 2
#   design cycles per deployed window, matrix code M2; mode-dependent rows, the AEB rows differ
#   from the SPORT rows, every handoff unsat, uniform rows decline, matrix code M5). S and M come
#   from the profile (the bandwidth scaling it is), D from the AEB. Batch I9 (2026-10-27): back
#   from benchmarks/reserve/ as the round-A time-scaled design (the batch-I2 suite file read SPORT
#   as a shorter time gap at lambda 1, letters D, and went to the reserve in batch I8 as a special
#   case of platoon_linkloss); it takes the place of platoon_latency (D, the same right model).
#
# Shared platoon model (identical in platoon_linkloss, platoon3_linkloss). A lead vehicle cruises
# at the platoon reference speed v_ref = 25 m/s (90 km/h). Per link (follower behind its
# predecessor): the gap g (m, bumper to bumper) and the range rate r = v_pred - v (m/s, positive
# = opening), g' = r. Units m, m/s, s.
# Spacing policy (constant time gap): standstill distance d0 = 5 m. CACC: time gap h_c = 0.6 s on
#   the V2V-broadcast reference speed, desired gap d0 + h_c v_ref = 20 m.
# CACC (V2V predecessor-acceleration feed-forward): a = a_pred + kp (g - d0 - h v_ref) + kd r, so
#   r' = -kp (g - d0 - h v_ref) - kd r with kp = 0.125 /s^2, kd = 0.75 /s: closed-loop poles 0.25
#   and 0.5 /s (over-damped); the forms r + 0.25 (g - 20) and r + 0.5 (g - 20) decay at 0.5 and
#   0.25 /s.
# SPORT driver profile: the CACC at 1.2 x its bandwidth, kp = 0.18 /s^2 (1.2^2 x), kd = 0.9 /s
#   (1.2 x): poles 0.3 and 0.6 /s, same time gap and desired gap (a bandwidth scaling of the
#   second-order loop: every rate 1.2 times the NORMAL's, so the SPORT follower's response is the
#   NORMAL response run 6/5 times faster).
# AEB (radar, the same function on every vehicle): triggers when the time to reach the standstill
#   distance at the current closing rate falls below T = 2 s, (g - d0) + T r < 0, i.e.
#   g + 2 r < 5; it then matches the predecessor's speed, r' = -0.5 r (relative deceleration
#   5 m/s^2 at the rated 10 m/s closing rate), which conserves the projected stop gap g + 2 r, and
#   stays latched until the driver resumes (not modeled). Trigger region as modeled:
#   0 <= g + 2 r < 5 (a projected stop gap below 0 is a collision the matching law cannot avoid).
# CACC operating range (the engagement spec, the same on both sides): |r| <= 10 (rated closing
#   rate) and 5 <= g + 2 r <= 60 (TTC to the standstill distance at least 2 s, and the gap
#   projected 2 s ahead inside the 60 m radar range gate). Forward invariant under both profiles:
#   d/dt (g + 2 r) = -0.25 (g + 2 r - 20) under NORMAL and -0.3 (g + 2 r - 20) under SPORT, so
#   the TTC floor is a sublevel set of the slow mode and neither CACC triggers the AEB (the
#   design's CACC -> AEB edge is pruned by a non-connection certificate).
# Control period 0.1 s on both sides (10 Hz V2V messages, the ETSI CAM / SAE BSM rate).
# Domain per link (both sides, every mode): 0 <= g <= 60 m (radar range gate), |r| <= 10 m/s
#   (rated closing rate); every mode's guard is forward invariant inside it.
#
# This file: one link (state g, r).
# Right (design follower): the CACC in its NORMAL profile, h = 0.6 s (desired gap 20 m), on the
#   operating range, next [CACC, AEB]; AEB latched. The same right model as platoon_linkloss
#   (Assumption 1 through the shared PlatoonCaccAeb lemmas).
# Left (deployed follower): the driver has selected SPORT, the CACC at 1.2 x bandwidth (kp 0.18,
#   kd 0.9, the same 0.6 s time gap and 20 m desired gap) on the same operating range,
#   next [SPORT, AEB]; the same AEB, latched.
# One cause: the driver profile (the bandwidth it selects). Same plant, time gap, AEB, operating
# range and control period (0.1 s on both sides) on both sides.
#
# Property (Delta = L - R), lambda in [1, 1.2]: the SPORT pairing at the bandwidth ratio 6/5, the
# AEB pairing at 1 (the range admits the per-pairing choice; both end points are stated values).
#   SPORT rows (exact): g_L = g_R and r_L = 1.2 r_R at the re-timed instants, written in the two
#     modal coordinates of the loop, (r_L - 1.2 r_R) + 0.3 (g_L - g_R) = 0 and (r_L - 1.2 r_R) +
#     0.6 (g_L - g_R) = 0 (four inequalities). Reading: the SPORT follower's gap at time t is the
#     NORMAL follower's gap at time 1.2 t, and its closing rate 1.2 times the NORMAL's there (the
#     time derivative of a re-timed signal): every gap profile of the SPORT follower is a sped-up
#     NORMAL profile, so the design's spacing safety (minimum gap, no AEB trigger from the operating
#     range) carries over to the SPORT profile with every event 6/5 times sooner. Exact, no
#     tolerance constant; it is the specification of the profile (a bandwidth scaling).
#     g_L >= 5 and g_L + 2 r_L >= 5: collision freedom of the deployed (gap at least d0 = 5 m) and
#     its TTC to d0 at least 2 s; the TTC floor keeps the deployed out of the AEB trigger from the
#     operating range (the handoff SPORT -> AEB is then unsat), the gap floor is the requirement.
#   AEB rows: exact, Delta r = 0 and Delta (g + 2 r) = 0 (the same AEB on both cars, at lambda 1).
# The stretch follows the cause: lambda = 6/5 is the bandwidth ratio of the two profiles (the
# rate scaling of the second-order loop). It is stated, not searched; as every exact rate ratio of
# this suite the SPORT rows certify at the exact ratio only: the whole file pinned to 1.2 DECLINES
# because the AEB pairing then has no lambda-1 segment (measured 2026-10-27), and RELCERT_SYNC=1
# DECLINES (the SPORT rows at lambda 1). Not implied by the domains; every left mode has a
# satisfiable start (g = 20, r = 0 on both sides for SPORT; g = 3, r = 0 for AEB).
# Cause dependence: with the NORMAL profile on both sides the exact claim (g_L = g_R, r_L = r_R)
# certifies at lambda 1 (no S); the ratio is the profile's.
#
# Why the rows differ (D). The SPORT rows carry the TTC floor, so the handoff SPORT -> AEB is unsat
# (a SPORT state never satisfies the AEB trigger: the deployed's AEB is reachable only as a start);
# the AEB rows are the exact matching rows at lambda 1, which the re-timed SPORT rows are not
# (r_L = 1.2 r_R against r_L = r_R). The uniform candidates decline (the SPORT rows in AEB, the
# AEB rows in SPORT, and their conjunction): D under both the current and the strict rule. Not
# load-bearing here: the design's CACC -> AEB edge is pruned (non-connection on the TTC floor),
# RELCERT_NO_PRUNE=1 also certifies (the existential choice closes the same fallback; only
# NO_PRUNE+NO_CHOICE declines: no P); no committed choice is needed (no X).
#
# Coverage of the right guards (domain 0 <= g <= 60, |r| <= 10): CACC and AEB together cover
# every domain state with 0 <= g + 2 r <= 60; the states with g + 2 r < 0 (collision
# unavoidable) or g + 2 r > 60 are in no right guard and no run reaches them (both guards are
# forward invariant).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, measured 2026-10-27, batch I9): CERTIFIED (about
# 6 s with a build running beside it; about 2 s quiet); CERTIFIED under RELCERT_NO_PRUNE=1,
# RELCERT_NO_CHOICE=1, without RELCERT_IMPLIED_CUT, RELCERT_NO_IMPLIED_CUT=1,
# RELCERT_NO_LINEAR_CUT=1, RELCERT_NO_CUT=1, RELCERT_NO_REPO=1, RELCERT_WELLFORMED_STRICT=1 and
# RELCERT_OPREGION=1 (every admitted start in some right guard); DECLINED under RELCERT_SYNC=1,
# SYNC+NO_CHOICE and NO_PRUNE+NO_CHOICE. Covers: SPORT_L at lambda 6/5, budget 2, admissible
# [CACC], joint steps retaining CACC only (no branching); AEB_L at lambda 1, budget 1, admissible
# [AEB]; pruned CACC -> AEB. --handoff 3/3 pass (rows differ, unsat). relcert --wellformed: CACC
# ok (invariant), AEB ok (invariant), 0 UNKNOWN, 0 BLOCKING. Letters: S M D.
[problem]
name = platoon_profiles
max_depth = 8
lambda_min = 1.0
lambda_max = 1.2
bound_T = 4.0
[Lsys]
state_vars = [g, r]
epsilon = 0.1
[Lsys.mode.SPORT]
ode = g' = smt2:r; r' = smt2:(- (* -0.18 (- g 20.0)) (* 0.9 r));
guard = r >= -10.0 and r <= 10.0 and g + 2.0 * r >= 5.0 and g + 2.0 * r <= 60.0
evolve = g >= 0.0 and g <= 60.0 and r >= -10.0 and r <= 10.0
next = [SPORT, AEB]
[Lsys.mode.AEB]
ode = g' = smt2:r; r' = smt2:(* -0.5 r);
guard = g + 2.0 * r < 5.0 and g + 2.0 * r >= 0.0 and g >= 0.0
evolve = g >= 0.0 and g <= 60.0 and r >= -10.0 and r <= 10.0
next = [AEB]
[Rsys]
state_vars = [g, r]
epsilon = 0.1
[Rsys.mode.CACC]
ode = g' = smt2:r; r' = smt2:(- (* -0.125 (- g 20.0)) (* 0.75 r));
guard = r >= -10.0 and r <= 10.0 and g + 2.0 * r >= 5.0 and g + 2.0 * r <= 60.0
evolve = g >= 0.0 and g <= 60.0 and r >= -10.0 and r <= 10.0
next = [CACC, AEB]
[Rsys.mode.AEB]
ode = g' = smt2:r; r' = smt2:(* -0.5 r);
guard = g + 2.0 * r < 5.0 and g + 2.0 * r >= 0.0 and g >= 0.0
evolve = g >= 0.0 and g <= 60.0 and r >= -10.0 and r <= 10.0
next = [AEB]
[relational_invariant]
SPORT = smt2:(and (>= (+ (- L_r (* 1.2 R_r)) (* 0.3 (- L_g R_g))) 0.0) (<= (+ (- L_r (* 1.2 R_r)) (* 0.3 (- L_g R_g))) 0.0) (>= (+ (- L_r (* 1.2 R_r)) (* 0.6 (- L_g R_g))) 0.0) (<= (+ (- L_r (* 1.2 R_r)) (* 0.6 (- L_g R_g))) 0.0) (<= L_g 5.0) (>= (+ L_g (* 2.0 L_r)) 5.0))
AEB = smt2:(and (>= (- L_r R_r) 0.0) (<= (- L_r R_r) 0.0) (>= (+ (- L_g R_g) (* 2.0 (- L_r R_r))) 0.0) (<= (+ (- L_g R_g) (* 2.0 (- L_r R_r))) 0.0))
