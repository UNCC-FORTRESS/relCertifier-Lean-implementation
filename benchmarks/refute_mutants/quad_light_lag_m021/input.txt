# quad_light_lag: the 20 %-lighter quadrotor against the reference model, both with the same
# motor thrust lag; altitude conformance up to a time scaling.
# scenario: model-refinement
# mechanisms: S M (time stretch lambda = 6/5 needed, RELCERT_SYNC=1 declines; multi-step cover,
#   matrix codes M1 M2)
#
# System. The climb segment of quad_light_airframe_20 (in benchmarks/reserve/ since 2026-10-27,
# batch I7; same airframe numbers) with the motors'
# thrust lag: altitude h (m), climb rate w (m/s), net specific thrust a = T/m - g (m/s^2), time
# in s. The propellers realise the climb thrust through a first-order lag of time constant
# tau = 0.1 s (motor and ESC spin-up), T' = (T_cmd - T)/tau, so a' = 10 (a_cmd - a) on either
# airframe; w' = a - K w, h' = w, where K w is not aerodynamic drag (a small quadrotor's heave
# damping is 0.1-2 /s, giving 5-100 m/s terminal climbs) but the closed-loop climb-rate response:
# the autopilot's P velocity loop commands thrust T = m_R (g + K (w_sp - w)) for the reference
# mass m_R with K = 4.905 /s (PX4's MPC_Z_VEL_P_ACC default is 4 /s) and set point w_sp = 2 m/s.
# As modeled, the set-point part of the command (hover thrust plus K w_sp) passes through the
# motor lag as a, and the feedback part K w acts on w without lag (the lag-free loop of
# quad_light_profiles kept under the lag: a simplification of the deployed loop, not a plant
# parameter).
#   Right (reference model): a_cmd = K w_sp = 9.81, k/m_R = K = 4.905 /s (terminal 2.0 m/s).
#   Left (deployed): the same loop, thrust command and lag on the airframe 20 % lighter
#     (m_R/m_L = 1.25): a_cmd = 0.25 g + 1.25 K w_sp = 14.715, k/m_L = 1.25 K = 6.13125 /s
#     (terminal 2.4 m/s); both scale by 1.25 because the loop commands thrust for m_R.
# K = 4.905 = g/2 is the gain at which the terminal rates are 2.0 and 2.4 m/s and the ratio is the
# round 6/5. The ratio is not grid-tuned: with PX4's default K = 4.0 /s (terminals 2.0 and 2.4905)
# the same rows certify pinned at lambda = 1 + 0.2 g / (K w_sp) = 1.24525, and with K = 4.5
# (terminals 2.0 and 2.436) at 1.218, Psi rebuilt for the new constants and the letters S M
# unchanged (re-measured 2026-10-29 on the one domain, where these gains leave the reference's box
# open at the limiter: 14.715 > 3 K, relcert --wellformed CLIMB BLOCKING). At every K the claim
# certifies only with the exact ratio on the stretch grid, pinned or as the top of a range
# ([1, 1.24525] certifies, [1, 1.3] and [1, 1.5] decline at K = 4.0), because Psi is conserved at
# the exact ratio only; the pin is the stated form.
# One cause: the airframe mass (the lag is the same physical lag on both sides).
#
# Requirement: the altitude conformance of quad_light_airframe_20, |h_L - h_R| <= 0.8 m at times t
# and (6/5) t; 0.8 m is the altitude acceptance radius (PX4's default NAV_MC_ALT_RAD).
# Stretch pinned (2026-10-27, final audit): lambda_min = lambda_max = 6/5 = 2.4 / 2, the ratio of the
# terminal climb rates, which the stated mass ratio and loop gain fix, lambda = 1 + 0.2 g / (K w_sp)
# (as in quad_light_airframe_20 since round A).
# The previous range [1, 2] certified only because 6/5 is a point of the tool's 21-point stretch grid
# (1 + 4/20); with lambda_max 4 (step 3/20) the same claim DECLINES. At any other lambda the
# steady-climb gap Psi below drifts (Psi' = 2.4 - 2 lambda), so no range can be stated.
#   rows 1, 2 (the requirement): h_R - h_L <= 0.8 and h_L - h_R <= 0.8.
# Strengthening rows (each needed: dropping either, or both, DECLINES):
#   rows 3, 4: -0.16 <= Psi <= 0.16 with Psi = (h_L - h_R) + ((w_L - 2.4) + 0.1 (a_L - 14.715))
#     / 6.13125 - ((w_R - 2) + 0.1 (a_R - 9.81)) / 4.905 (written multiplied by 6.13125). Each
#     side's h + ((w - w_term) + tau (a - a_cmd)) / (k/m) is its extrapolated steady-climb
#     altitude and grows at exactly its terminal rate whatever the lag state, so at
#     lambda = 6/5 = 2.4 / 2 their difference Psi is conserved exactly.
#     Constant: the requirement 0.8 m less the largest transient term the earlier per-side climb
#     envelopes allowed (0.63 m above, 0.61 m below), rounded down. On the one domain the term
#     reaches 0.94 m above and 0.71 m below, so rows 1 and 2 no longer follow from the box.
# The lag breaks the lag-free climb-rate row 1.2 w_R <= w_L of quad_light_airframe_20: at the
# scaled time the reference's lag is 1.2 times shorter, so from hover its climb rate stays above
# the deployed's through the whole transient (simulated; adding that row DECLINES). The gap's
# sign flips against quad_light_airframe_20: from hover (h_L = h_R, w = a = 0 on both)
# Psi = -0.0237 m and the deployed falls behind the scaled reference by at most 2.4 cm
# (simulated: gap from 0 down to -0.0237 m, never positive); the lower row 1 is now the one the
# lag loads.
# Tightest (bisection to 0.01, re-measured 2026-10-29 on the one domain; the wider box admits
# starts with larger transients): with rows 3, 4 at 0.16, row 2 certifies down to 0.51 (0.50
# declines; 0.40 before) and row 1 down to 0.38 (0.37 declines); with rows 1, 2 at 0.8, Psi's
# bounds certify up to 0.45 above (0.46 declines; 0.56 before) and 0.58 below (0.59 declines);
# with Psi in [-0.03, 0.01] (hover still related) rows 1 and 2 certify down to 0.36 (0.35
# declines; 0.25 before). Psi is conserved, so its own bounds are only limited by the starts. Not
# implied by the domains.
#
# Guards and domains. One domain on both sides, CLIMB guard = evolve: h >= 0 (the ground),
# 0 <= w <= 3 m/s (w >= 0 the climb segment as in quad_light_profiles; w <= 3 the PX4 climb-rate
# limiter MPC_Z_VEL_MAX_UP, the bound the domain audit of 2026-10-29 gave quad_light_profiles),
# 0 <= a <= 14.715 m/s^2 = 1.5 g (net specific thrust from hover to the propulsion's thrust
# limit). The box is forward invariant on both sides (a' >= 0 at a = 0, a' <= 0 at 14.715,
# w' = a >= 0 at w = 0, h' = w >= 0); at the limiter w' = a - (k/m) w <= 0 needs a <= 3 k/m, which
# on the reference is exactly the thrust limit 14.715, so the a bound keeps its box forward
# invariant (relcert --wellformed: CLIMB ok (invariant)). Guard = evolve stays: with per-side
# guards narrower than the domain the tool's Assumption 1 check returns UNKNOWN (measured).
# Altitude unbounded above. One right mode (no coverage gap); the left mode has a satisfiable
# start (hover). Control interval 1 s on both sides; budget ceil(6/5) = 2 (M).
# One domain (2026-10-29): per-side climb envelopes (left w <= 2.4, right w <= 2.0, a <= 9.81: the
# terminal rates and thrust commands) -> the one physical box above; rows unchanged, CERTIFIED
# without the envelopes; three tight values moved (above).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, re-measured 2026-10-29 on the one domain, the
# same as before it): CERTIFIED (0.3 s); DECLINED under RELCERT_SYNC=1 and SYNC+NO_CHOICE;
# CERTIFIED under RELCERT_NO_PRUNE=1, RELCERT_NO_CHOICE=1, NO_PRUNE+NO_CHOICE, without
# RELCERT_IMPLIED_CUT, NO_IMPLIED_CUT, NO_LINEAR_CUT, RELCERT_NO_CUT=1, RELCERT_NO_PAIR_STRETCH=1,
# the operating region (every admitted start in some right guard), RELCERT_WELLFORMED_STRICT=1 and
# every two-sided evolve bound widened by 20 % of its range. Cover: CLIMB at lambda = 6/5, budget
# 2, admissible start CLIMB, nothing pruned; --handoff 1/1 vacuous; relcert --wellformed: CLIMB ok
# (invariant). Units m, m/s, m/s^2, s.
