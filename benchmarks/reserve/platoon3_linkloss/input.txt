# integration. Reason: links 2 and 3 are exact copies of link 1; replaced in the suite by
# platoon_latency. The header below is the design's.
#
# platoon3_linkloss: a string of three CACC followers whose first follower intermittently loses
# its V2V link (jamming at the head of the string) and then degrades to radar-only ACC, against
# the design string with every link up; the three-follower version of platoon_linkloss.
# scenario: dos-attack
# mechanisms: D (mode-dependent rows: the AEB rows differ from the CACC/ACC1 row, every handoff
#   unsat or implied, matrix code M5); scaling point of platoon_linkloss (6-D, 5 / 4 modes)
#
# Shared platoon model (identical in platoon_linkloss, platoon_profiles, platoon3_linkloss,
# platoon3_profiles). A lead vehicle cruises at the platoon reference speed v_ref = 25 m/s
# (90 km/h). Per link (follower behind its predecessor): the gap g (m, bumper to bumper) and the
# range rate r = v_pred - v (m/s, positive = opening), g' = r. Units m, m/s, s.
# Spacing policy (constant time gap): standstill distance d0 = 5 m. CACC: time gap h_c = 0.6 s on
#   the V2V-broadcast reference speed, desired gap d0 + h_c v_ref = 20 m. Radar-only ACC fallback:
#   time gap h_a = 1.2 s on the follower's own speed v = v_ref - r (35 m at cruise).
# CACC (V2V predecessor-acceleration feed-forward): a = a_pred + kp (g - 20) + kd r, so
#   r' = -kp (g - 20) - kd r with kp = 0.125 /s^2, kd = 0.75 /s: closed-loop poles 0.25 and
#   0.5 /s (over-damped); the forms r + 0.25 (g - 20) and r + 0.5 (g - 20) decay at 0.5 and
#   0.25 /s.
# ACC fallback (no feed-forward): a = kp (g - d0 - h_a v) + kd_a r, kd_a = 0.6 /s chosen so that
#   the loop keeps the CACC poles (kd_a + kp h_a = 0.75): r' = -kp (g - 35) - 0.75 r.
# SPORT driver profile: the CACC at 1.2 x its bandwidth, kp = 0.18 /s^2 (1.2^2 x), kd = 0.9 /s
#   (1.2 x): poles 0.3 and 0.6 /s, same time gap and desired gap.
# AEB (radar, the same function on every vehicle): triggers when the time to reach the standstill
#   distance at the current closing rate falls below T = 2 s, (g - d0) + T r < 0, i.e.
#   g + 2 r < 5; it then matches the predecessor's speed, r' = -0.5 r (relative deceleration
#   5 m/s^2 at the rated 10 m/s closing rate), which conserves the projected stop gap g + 2 r, and
#   stays latched until the driver resumes (not modeled). Trigger region as modeled:
#   0 <= g + 2 r < 5 (a projected stop gap below 0 is a collision the matching law cannot avoid).
# CACC operating range (the engagement spec, the same on both sides): |r| <= 10 (rated closing
#   rate) and 5 <= g + 2 r <= 60 (TTC to the standstill distance at least 2 s, and the gap
#   projected 2 s ahead inside the 60 m radar range gate). Forward invariant under CACC, ACC and
#   SPORT: d/dt (g + 2 r) = -0.25 (g + 2 r - 20) under CACC (-0.25 (g + 2 r - 35) under ACC), so
#   the TTC floor is a sublevel set of the slow mode and the CACC never triggers the AEB (the
#   design's CACC -> AEB edges are pruned by non-connection certificates); the |r| <= 10 faces
#   hold for every gap below 70 m.
# Control period 0.1 s on both sides (10 Hz V2V messages, the ETSI CAM / SAE BSM rate).
# Domain per link (both sides, every mode): 0 <= g <= 60 m (radar range gate), |r| <= 10 m/s
#   (rated closing rate); every mode's guard is forward invariant inside it (CACC/ACC/SPORT: the
#   operating range; AEB: g + 2 r is conserved and r decays).
#
# This file: three links, state (g1, r1, g2, r2, g3, r3); link i is follower i behind its
# predecessor (link 1 behind the leader). Each follower's CACC feeds its predecessor's
# acceleration forward, so every link obeys the single-link law of the shared model.
# Right (design string, every link up): CACC on all three links, guard the operating range of
#   every link, next [CACC, AEB1, AEB2, AEB3]; AEBk: follower k's AEB (link k on the AEB law, the
#   two other links on the CACC), guard link k in the trigger region and the two other links in
#   their operating range, latched (next [AEBk]).
# Left (deployed string): the same CACC and the same AEB modes (AEBk from CACC, latched), plus
#   the fallback of follower 1: when its V2V link is lost it degrades to the radar-only ACC
#   (h_a = 1.2 s) on link 1, ACC1 (links 2 and 3 keep V2V from their predecessors and the CACC
#   law); when the link is back it re-engages the CACC. CACC -> [CACC, ACC1, AEB1, AEB2, AEB3],
#   ACC1 -> [ACC1, CACC]. ACC1 lists no AEB: its row keeps every TTC >= 2 s, so no AEB is entered
#   from it (a braking follower behind an ACC follower 1 would be a further mode, not modeled).
# One cause: the loss of follower 1's link (the fallback it forces). Same plant, laws, AEB,
# operating range and control period on both sides; lambda_min = lambda_max = 1 (same time).
#
# Property (Delta = L - R; rows CACC and ACC1 identical, AEBk separate).
#   CACC, ACC1:
#     link 1: 0 <= Delta g1 <= 15, Delta r1 + 0.25 Delta g1 in [0, 3.75], Delta r1 + 0.5 Delta g1
#       in [0, 7.5], g1_R + 2 r1_R >= 5, as in platoon_linkloss: follower 1 never closer than
#       the design and at most (h_a - h_c) v_ref = 15 m farther behind however often its link
#       drops; the design's follower 1 stays engaged (strengthening, needed: 4.99 declines).
#       Tight: 15.00 certifies, 14.99 declines; 0.00 certifies, 0.01 declines.
#     links 2, 3: exact, Delta r_i + rho Delta g_i = 0 (rho = 0.25, 0.5), i.e. g_i_L = g_i_R and
#       r_i_L = r_i_R. Requirement (string stability of the fallback): the loss at the head of
#       the string must not propagate; it does not, because followers 2 and 3 cancel their
#       predecessor's motion through the feed-forward.
#     every link: g_i_L >= 5 and g_i_L + 2 r_i_L >= 5, collision freedom (standstill distance)
#       and TTC to d0 at least 2 s of every deployed follower; gap floor tight (5.01 declines),
#       the TTC floor is the AEB threshold (larger floors also certify).
#   AEBk: exact on every link (link k in the AEB forms Delta r_k = 0, Delta (g_k + 2 r_k) = 0,
#     the other links in the CACC forms).
# The AEB is placed by the claim and the cover, not by start floors (every left guard is the
# spec's region, identical to the right's): the design's AEBk is no admissible start of CACC_L
# or ACC1_L (links 2, 3 exact, link 1 by its engaged row), AEBk_L is paired with AEBk_R (exact,
# lambda 1), the design's CACC -> AEB1, AEB2, AEB3 edges are pruned (non-connection on each TTC
# floor), and the handoffs CACC -> AEBk are unsat (the CACC row keeps every TTC >= 2 s).
#
# Coverage of the right guards (per-link domain 0 <= g_i <= 60, |r_i| <= 10): a state with two
# or more links below the TTC floor, or any link with g_i + 2 r_i < 0 or > 60, is in no right
# guard; no run reaches one (the CACC operating range is forward invariant, and AEBk keeps the
