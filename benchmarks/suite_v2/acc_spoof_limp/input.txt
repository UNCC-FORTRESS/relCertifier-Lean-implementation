# acc_spoof_limp: spoofed cruise control with a fault-latched limp-home mode, against a reference
# with driver-selectable set speeds; the spoofed car must never be faster than the reference and
# never slower than the following traffic can absorb.
# scenario: sensor-attack
# mechanisms: M B I (multi-step covers; branching joint steps; checked cuts, RELCERT_NO_CUT=1
#   declines; matrix codes M2 M3 M6)
#
# System. Speed v (m/s), time s; one car, speed loop of gain 0.5 /s (speed-loop form, no lag).
#   Left (deployed, attacked): the fused speed signal is spoofed to read 25 % high (1.25 v), so
#     CRUISE v' = 0.5 (30 - 1.25 v) = 0.625 (24 - v): the car settles at 24 m/s. Its plausibility
#     monitor compares the fused speed with the wheel-speed sensor; when it flags the mismatch the
#     controller LATCHES a limp-home mode until the next ignition cycle: LIMP v' = 0.3 (22 - v)
#     (the loop reads the unspoofed wheel speed, set speed 22 m/s = 80 km/h, soft gain 0.3 /s).
#     CRUISE -> LIMP may happen at any decision; there is no way back.
#   Right (reference): the unspoofed controller; the driver selects ECO 27, NORMAL 30 or SPORT
#     33 m/s at any time (gain 0.5 /s; NORMAL <-> ECO / SPORT), and below the 20 m/s ACC floor
#     every mode hands back to the driver: DISENGAGE v' = -0.1 v (a coast-down of engine-braking
#     order, 2 m/s^2 at the floor), latched. The field is pruned on every edge (below), so the
#     verdict never depends on it.
# One cause: the spoof (the limp-home latch is the deployed's own response to it).
# Control intervals: 2 s on the left, the plausibility monitor's debounce window (the deployed's
# only mode decision, the latch, is taken at most every 2 s); 1 s on the right, the reference's
# mode logic (set-speed selection, ACC floor). With equal 1 s intervals the file still certifies
# but keeps only I (budget 1, no multi-step or branching cover).
# Where the letters come from (final audit, 2026-10-27). M and B come from the 2 s debounce period of
# the deployed's plausibility monitor (the second difference between the sides, stated above), not
# from the spoof: with equal 1 s periods only I remains. I persists without the spoof (the left
# reading the true speed, still latching LIMP; the reference still able to DISENGAGE: RELCERT_NO_CUT=1
# still DECLINES). So no letter of this file comes from the spoof itself; the spoof sets the bounds
# (row 1's 4.8 m/s margin, row 2's intercept).
#
# Guards. CRUISE and the reference's three set-speed modes engage at the ACC floor 20 m/s (CRUISE
# 20 <= v < 40, the set-speed modes 20 <= v <= 40); LIMP is entered between 20 and 30 m/s, the
# ACC's nominal set-speed band (a limp-home cap of 110 km/h = 30.6 m/s certifies identically).
# The ceiling is not load-bearing for the verdict: with LIMP admitted on the whole domain (up to
# 40 m/s) the file still CERTIFIES, and against every driver selection (RELCERT_NO_CHOICE=1) it
# certifies up to 34.50 m/s (34.51 declines), the speed above which ECO (0.5 (27 - v))
# decelerates faster than the limp map (0.3 (22 - v)); above it the cover must commit the driver
# away from ECO (hop ECO -> NORMAL), which would add X. DISENGAGE
# v < 20. The right guards partition the domain [0, 40] (no coverage gap). Physical domain
# 0 <= v <= 40 m/s on both sides (the vehicle's speed range on this road class); every mode is
# forward invariant on it; every left mode has a satisfiable start (v_L = v_R).
#
# Property (the same two rows in both left modes; the requirements do not depend on the mode).
#   Row 1, overspeed: v_L <= v_R, a spoofed speed sensor must never make the car faster than the
#     unspoofed reference. Constant 0 is forced: v_L <= v_R + 0.01 DECLINES (the reference could
#     then start disengaged below the floor); the row certifies down to v_L <= v_R - 4.80
#     (-4.81 declines): the spoof keeps the car at least 4.8 m/s slower along the cover.
#   Row 2, traffic flow: the closing speed v_R - v_L at which the following traffic (driving at
#     the reference's speed v_R) closes on the spoofed car must stay absorbable: a follower at the
#     2 s time gap (gap 2 v_R) with the AASHTO stopping-sight-distance design values,
#     perception-reaction time 2.5 s and deceleration 3.4 m/s^2, sheds a closing speed dv that
#     appears at once without contact iff 2.5 dv + dv^2 / 6.8 <= 2 v_R, i.e.
#     dv <= -8.5 + sqrt(72.25 + 13.6 v_R): 10.05 m/s at 20 m/s, 16.32 m/s at 40 m/s. The bound is
#     concave in v_R, so its chord lies below it; the row takes the linear bound
#     dv <= 4 + 0.3 v_R (10 at 20 m/s, 16 at 40 m/s, below the chord), i.e. 0.7 v_R <= v_L + 4.
#     The spoofed car slows gradually, so a step is the worst case.
#     Tightest (bisection to 0.01, the intercept 4; measured 2026-10-28): with the existential
#     choice both modes together certify down to -0.20 (-0.21 declines; LIMP binds; the cover
#     then commits the reference away from SPORT, hop SPORT -> NORMAL in both left modes; CRUISE
#     alone, LIMP at 4, down to -3.00); against every driver selection (RELCERT_NO_CHOICE=1, no
#     committed choice) down to 1.90 (1.89 declines; CRUISE alone 0.08, 0.07 declines; LIMP
#     binds at 1.90). So the closing speed stays below 0.3 v_R + 1.9 m/s against every selection:
#     a margin of 2.1 m/s on the requirement, 4.2 m/s with the choice.
# Rows identical in both modes, so the file is not mode-keyed (--handoff 3/3, vacuous). Not
# implied by the domains. Against every driver selection: the cover needs no committed choice at
# the stated intercept 4 (RELCERT_NO_CHOICE=1 certifies). With a speed-independent closing bound
# (the 20 m/s value, v_R <= v_L + 10) the limp car at 22 m/s against SPORT traffic at 33 m/s
# closes at 11 m/s and
# the cover must commit the reference away from SPORT; the speed-dependent row above is the
# requirement and needs no such choice.
#
# Pruning. Every reference mode declares DISENGAGE below the 20 m/s floor; each set-speed loop
# accelerates at the floor and is entered above it, so NORMAL, ECO, SPORT -> DISENGAGE are pruned
# by non-connection certificates; v_L >= 20 and v_L <= v_R exclude DISENGAGE as a start. Pruning
# is redundant here: RELCERT_NO_PRUNE=1 certifies (the joint steps then also cover DISENGAGE),
# only RELCERT_NO_PRUNE=1 RELCERT_NO_CHOICE=1 declines (no P).
# Branching (B). In both windows the joint step from NORMAL retains ECO and SPORT (branch 2).
# Mode facts (I). The engagement floor v >= 20 of every engaged mode, kept by its flow, is a
# checked cut: without cuts (RELCERT_NO_CUT=1) row 1 fails in CRUISE against ECO (at v_L = v_R
# the spoofed loop accelerates harder than ECO's below 12 m/s) and in LIMP against DISENGAGE, and
# the file DECLINES.
#
# Stretch pinned (2026-10-27, final audit): lambda_max 6 -> 1. Both covers were at lambda 1 and the
# traffic-flow requirement is a real-time one (the follower closes in real time), so the unused
# range [1, 6] is gone; verdicts and letters unchanged.
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, re-measured 2026-10-27 at lambda_max 1 and
# 2026-10-28): CERTIFIED (0.25 s); CERTIFIED under RELCERT_SYNC=1,
# RELCERT_NO_PRUNE=1, RELCERT_NO_CHOICE=1, SYNC+NO_CHOICE, without RELCERT_IMPLIED_CUT,
# NO_IMPLIED_CUT, NO_LINEAR_CUT, the operating region (every admitted start in some right guard)
# and RELCERT_WELLFORMED_STRICT=1; DECLINED under NO_PRUNE+NO_CHOICE and RELCERT_NO_CUT=1.
# Covers: CRUISE and LIMP at lambda = 1, budget 2, admissible starts NORMAL, ECO, SPORT; pruned
# NORMAL, ECO, SPORT -> DISENGAGE. relcert --wellformed: all four right modes ok (invariant).
# The right model differs from the 2026-10-27 file in its DISENGAGE field (-0.5 v -> -0.1 v,
# 2026-10-28; same reference model as acc_tune_limp); its Assumption 1 proof
# (WellFormed/AccSpoofLimp.lean) states the new field. Units m/s, s.
[problem]
name = acc_spoof_limp
max_depth = 8
lambda_min = 1.0
lambda_max = 1.0
bound_T = 4.0
[Lsys]
state_vars = [v]
epsilon = 2.0
[Lsys.mode.CRUISE]
ode = v' = smt2:(* 0.5 (- 30.0 (* 1.25 v)));
guard = v >= 20.0 and v < 40.0
evolve = v >= 0.0 and v <= 40.0
next = [CRUISE, LIMP]
[Lsys.mode.LIMP]
ode = v' = smt2:(* 0.3 (- 22.0 v));
guard = v >= 20.0 and v <= 30.0
evolve = v >= 0.0 and v <= 40.0
next = [LIMP]
[Rsys]
state_vars = [v]
epsilon = 1.0
[Rsys.mode.NORMAL]
ode = v' = smt2:(* 0.5 (- 30.0 v));
guard = v >= 20.0 and v <= 40.0
evolve = v >= 0.0 and v <= 40.0
next = [NORMAL, ECO, SPORT, DISENGAGE]
[Rsys.mode.ECO]
ode = v' = smt2:(* 0.5 (- 27.0 v));
guard = v >= 20.0 and v <= 40.0
evolve = v >= 0.0 and v <= 40.0
next = [ECO, NORMAL, DISENGAGE]
[Rsys.mode.SPORT]
ode = v' = smt2:(* 0.5 (- 33.0 v));
guard = v >= 20.0 and v <= 40.0
evolve = v >= 0.0 and v <= 40.0
next = [SPORT, NORMAL, DISENGAGE]
[Rsys.mode.DISENGAGE]
ode = v' = smt2:(* -0.1 v);
guard = v < 20.0
evolve = v >= 0.0 and v <= 40.0
next = [DISENGAGE]
[relational_invariant]
CRUISE = smt2:(and (<= L_v R_v) (<= (* 0.7 R_v) (+ L_v 4.0)))
LIMP   = smt2:(and (<= L_v R_v) (<= (* 0.7 R_v) (+ L_v 4.0)))
