# acc_tune_lag: the retuned cruise loop against the stock loop, both with the same powertrain lag and
# the same control period.
# scenario: degraded-controller
# mechanisms: S M (time stretch lambda = 2 needed, RELCERT_SYNC=1 declines; multi-step cover: at
#   lambda = 2 each left window is matched by two right cycles; matrix codes M1 M2). Both letters
#   come from the retune: the stretch is the ratio of the two dominant time constants.
#
# System. Speed v (m/s) and realised acceleration a (m/s^2) of one car whose cruise loop commands
# a_cmd = k (30 - v) toward the set speed 30 m/s; the powertrain realises the command through a
# first-order lag of time constant tau = 0.32 s: v' = a, a' = (a_cmd - a) / tau = 3.125 (a_cmd - a).
# The pair isolates the control change: both sides are this car with this lag.
#   Left (deployed): the aftermarket retune, speed-loop gain k = 0.75 /s.
#   Right (reference): the stock calibration, gain k = 0.5 /s.
# Lag choice. tau = 0.32 s (1/tau = 25/8) is the lag at which BOTH closed loops have rational
# real roots, so both are non-oscillatory and decouple into exponential modes:
#   left  s^2 + 3.125 s + 2.34375 = (s + 1.25)(s + 1.875)
#   right s^2 + 3.125 s + 1.5625  = (s + 0.625)(s + 2.5).
# Control period: 0.1 s on BOTH sides (epsilon = 0.1; every decision interval is at most 0.1 s).
# The speed loop is continuous in the ODEs; the period is that of the mode decision (the
# engagement check). 0.1 s bounds the update cycle of an automotive ACC's long-range radar (the
# Continental ARS 408-21 data sheet gives a cycle time of about 72 ms). The gain is the only
# difference between the sides.
#
# Property (requirement). The retune's specification is "the stock response, twice as fast":
# the dominant (slow) mode must be the stock loop's dominant mode with its time constant halved
# (1.6 s -> 0.8 s). Let u = v + a / r_f be the dominant-mode speed (r_f the fast root:
# u_L = v_L + a_L / 1.875, u_R = v_R + a_R / 2.5); u - 30 decays at the slow rate (1.25 /s left,
# 0.625 /s right). Claim: u_L = u_R (two rows, 4.6875 v_L + 2.5 a_L = 4.6875 v_R + 1.875 a_R):
# at every instant the retuned car's dominant-mode speed equals the stock car's at twice the
# elapsed time. Exact: no tolerance constant. Not implied by the domains (it pins a_R given the
# other three coordinates).
# The claim depends on the cause: with a retune gain of 0.8 /s instead of 0.75 /s (same claim, same
# guards) the file DECLINES; the exact claim and its stretch 2 are the specification of this retune
# (the factor 2 is built into the specification, and it lies on the tool's stretch grid).
# Consequence (measured 2026-10-27, not part of the claim): adding |v_L - v_R| <= c as a row
# certifies down to c = 3.34 (3.33 declines; 2.89 on the round-A file, whose left guard was the
# engagement box): the fast modes keep the speeds within 3.34 m/s over the left envelope.
#
# Guards. Left: the retuned loop's ENGAGED ENVELOPE, the forward-invariant hull under the retuned
# loop of its engagement box (the controller engages, or resumes, between 25 m/s and the set speed
# with |a| <= 2 m/s^2, no hard pedal input): a + 1.25 (v - 30) in [-8.25, 2] and
# a + 1.875 (v - 30) in [-11.375, 2] (the left modal coordinates, decaying at 1.875 /s and
# 1.25 /s; the box's corners (25, -2) and (30, 2) are envelope corners). The guard is re-checked
# at every decision. With the box itself as the guard (the round-A file) a left run from (30, 2)
# overshoots 30 m/s (to 30.47) and would end there; with the envelope every left run from the box
# continues (they stay in v in [24.87, 30.47]).
# Right: the stock car's ENGAGED ENVELOPE, the forward-invariant hull of the same
# engagement box under the stock loop: a + 2.5 v in [60.5, 77] and a + 0.625 v in [13.625, 20.75]
# (the modal coordinates a + r (v - 30) of the box, each decaying toward 0, so the set is kept by
# the flow: relcert --wellformed CRUISE ok (invariant)). It bounds the reference's lag state,
# which a speed band alone does not (with v in [20, 40] and a free the reference blocks or
# leaves the band). The envelope spans v in [21.2, 33.8]; simulated runs from the engagement box
# stay in v in [24.8, 30.5].
# Coverage. States of the right domain outside the envelope are in no right guard: the
# reference never reaches them after engaging. The stock controller's disengage branch below
# 20 m/s is not modeled on this pair: neither loop comes near 20 m/s from engagement.
# Domains (both sides): v in [0, 40] m/s, a in [-10, 10] m/s^2 (1 g, the tyre-road limit);
# physical limits, not load-bearing.
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, measured 2026-10-27 on branch benchmark-fixes):
# CERTIFIED (0.19 s); DECLINED under RELCERT_SYNC=1 and SYNC+NO_CHOICE; CERTIFIED under
# RELCERT_NO_PRUNE=1, RELCERT_NO_CHOICE=1, NO_PRUNE+NO_CHOICE, without RELCERT_IMPLIED_CUT,
# RELCERT_NO_IMPLIED_CUT=1, RELCERT_NO_LINEAR_CUT=1, RELCERT_NO_CUT=1, RELCERT_OPREGION=1 and
# RELCERT_WELLFORMED_STRICT=1. Cover: lambda = 2, budget ceil(2 * 0.1 / 0.1) = 2 right cycles per
# left window, nothing pruned (matrix: M1 M2; the cuts are kept but not load-bearing). --handoff
# vacuous (one left mode). relcert --wellformed: CRUISE ok (invariant), 0 UNKNOWN, 0 BLOCKING. The
# right model changed only in its period (epsilon 1.0 -> 0.1; its Assumption 1 proof states the
# new interval). Units m/s, m/s^2, s.
[problem]
name = acc_tune_lag
max_depth = 8
lambda_min = 1.0
lambda_max = 6.0
bound_T = 4.0
[Lsys]
state_vars = [v, a]
epsilon = 0.1
[Lsys.mode.CRUISE]
ode = v' = a; a' = smt2:(* 3.125 (- (* 0.75 (- 30.0 v)) a));
guard = smt2:(and (>= (+ a (* 1.25 (- v 30.0))) (- 8.25)) (<= (+ a (* 1.25 (- v 30.0))) 2.0) (>= (+ a (* 1.875 (- v 30.0))) (- 11.375)) (<= (+ a (* 1.875 (- v 30.0))) 2.0))
evolve = v >= 0.0 and v <= 40.0 and a >= -10.0 and a <= 10.0
next = [CRUISE]
[Rsys]
state_vars = [v, a]
epsilon = 0.1
[Rsys.mode.CRUISE]
ode = v' = a; a' = smt2:(* 3.125 (- (* 0.5 (- 30.0 v)) a));
guard = smt2:(and (>= (+ a (* 2.5 v)) 60.5) (<= (+ a (* 2.5 v)) 77.0) (>= (+ a (* 0.625 v)) 13.625) (<= (+ a (* 0.625 v)) 20.75))
evolve = v >= 0.0 and v <= 40.0 and a >= -10.0 and a <= 10.0
next = [CRUISE]
[relational_invariant]
CRUISE = smt2:(and (<= (+ (* 2.5 L_a) (* 4.6875 L_v)) (+ (* 1.875 R_a) (* 4.6875 R_v))) (<= (+ (* 1.875 R_a) (* 4.6875 R_v)) (+ (* 2.5 L_a) (* 4.6875 L_v))))
