# charger_fast_tapers: a DC fast charger whose constant-current limit is raised 25 % and whose phase
# decision runs every other request cycle, against the certified charging profile replayed at the
# current ratio 5/4 with two taper options deciding on every cycle: a re-timed one-sided bound on
# the deployed state of charge.
# scenario: degraded-controller
# mechanisms: S M R B D I (time stretch lambda = 5/4, the raised CC current ratio, stated;
#   RELCERT_SYNC=1 declines, matrix code M1; multi-cycle matching, one deployed decision against
#   three replayed profile decisions, matrix code M2; right-only repositioning for the lag
#   pairings; branching joint steps, the profile's BULK segment retaining both tapers, matrix
#   code M3; mode-dependent rows; checked cuts, matrix codes M5 M6 M6+).
#   S comes from the cause (the raised limit), R, D and I from the claim form (a one-sided bound
#   against an existential reference), M and B from the decision-period ratio under the
#   re-timing. No P: the model has no edge a run could take that a non-connection certificate
#   excludes (below). No X: RELCERT_NO_CHOICE=1 certifies.
#
# System. State of charge x (%), time in min. The certified charging profile (right):
#   PRECHARGE   (0 <= x < 15):  x' = 0.2 (20 - x)    recovery charge of a deeply discharged cell
#                                                     (4 %/min at 0 %, 1 %/min at 15 %)
#   BULK        (15 <= x < 80): x' = 0.1 (100 - x)   constant-current phase (15 -> 80 % in about
#                                                     14.5 min, the DC fast-charging range)
#   ABSORB_SLOW (80 <= x < 99): x' = 0.05 (100 - x)  slow taper (80 -> 99 % in about 60 min)  } the
#   ABSORB_FAST (80 <= x < 99): x' = 0.07 (100 - x)  fast taper (80 -> 99 % in about 43 min)  } firmware
#                                                     selects one when it leaves BULK
#   FULL        (x >= 99):      x' = 0               hold
# The deployed unit (left) runs the profile with its constant-current limit raised 25 % (BULK
# 0.125: 15 -> 80 % in about 11.6 min) and is otherwise the profile with the slow taper: PRECHARGE
# 0.2 and ABSORB 0.05 are the profile's own values, because a raised current limit scales neither
# the precharge current (a cell-protection value) nor the constant-voltage taper (set by the
# cell's acceptance). Two differences: the CC current limit and the slower phase decision its
# firmware ships with (the control periods below). The guards partition [0, 100] on both sides (no
# coverage gap: the pre-charge phase covers [0, 15), a deeply discharged cell is recovered by the
# precharge current). The CC phase is the exponential x' = k (100 - x) on both sides (8.5 %/min at
# 15 %, 2.1 %/min at 79 % on the deployed), the time-constant form of the profile, not a constant
# rate; a constant-rate BULK (5.625 against 4.5 %/min, the same 15 -> 80 % times) was tested
# 2026-10-29 on the earlier form of this file and changed nothing in the certificate.
# Control periods. Right (certified profile): 0.006 min = 0.36 s (epsilon = 0.006): the phase
# decision follows the vehicle's charge-current request, sent on the CHAdeMO CAN cycle of 100 ms
# +- 10 % (CHAdeMO protocol), so 0.36 s bounds it with margin. Left (deployed unit): 0.012 min =
# 0.72 s (epsilon = 0.012): the firmware with the raised limit takes the phase decision on every
# other request cycle (it averages two consecutive current requests before changing phase, a
# design value of this file; the round-2 design had the same 2:1 ratio, 2 h against 1 h). Every
# decision interval is at most the period. Under the re-timing one deployed decision spans 2.5
# replayed profile decisions, budget ceil(5/4 * 0.012 / 0.006) = 3 (M). Time scale (2026-10-27,
# batch I7): the time unit is the minute (the earlier design used the hour with epsilon 0.0001 h);
# the rate constants are per minute, so the phases take the minutes of DC fast charging.
#
# Property (re-timed SoC lead): run against the certified profile replayed at the CC current ratio
# 5/4 (the profile's clock runs 1.25 times faster; lambda_min = lambda_max = 1.25, stated, not
# searched), the deployed state of charge never exceeds the replayed profile's by more than c = 1 %
# SoC in the CC phase, the taper and the hold, and never exceeds it in the pre-charge phase:
#   BULK, ABSORB, FULL: x_L <= x_R + 1;   PRECHARGE: x_L <= x_R.
# The pre-charge requirement is the strict one because there the deployed runs the profile's own
# precharge current (a cell-protection value), so any lead in that phase would be a precharge
# current the profile does not certify.
# The constant c = 1 is the tool's tight value, not a physical lead. Physically the deployed never
# leads the replayed profile at all (simulated 2026-10-29 from every common start x0 in {0, 5, 10,
# 15, 50, 80} with both tapers for the profile: re-timed lead 0.00, within the 0.005 % SoC of the
# simulation grid; at equal clocks it leads by up to 6.96 % SoC in the CC phase). Tightness
# (measured 2026-10-29, bisected): the rows certify at c = 1.00 and DECLINE at 0.99 (and at
# 0.999); every c tried above, up to 100, certifies. The one unit is the FULL pairing's
# asymptote-against-floor gap of the tool's over-approximation: a deployed cell still charging
# (x <= 100, the implied contraction cut) against a replayed cell at the FULL floor 99,
# independent of the deployed charger's rates and of the CC law; a forced ABSORB exit (evolve
# x <= 99) is not expressible (one evolve domain per side), so this unit stays. The physical gap in
# the hold is the sampling overshoot past 99 within one decision period (below 0.001 % SoC). The
# charging pairings themselves hold at any positive c (BULK_L x BULK_R, the CC phase, is a genuine
# joint segment at the stated rates).
# This is an upper bound on what the raised limit can buy, one-sided and re-timed. It is not an
# equal-time comparison (at equal clocks the deployed leads the profile by up to 7 % SoC in the
# CC phase, and no linear one-sided row is inductive there: RELCERT_SYNC=1 declines), and it is
# not a time-reparametrization identity (only the CC rate is raised, so the deployed run is not the
# profile's run at 5/4 speed: in PRECHARGE the replayed profile is 25 % faster than the deployed,
# in the taper the replayed slow taper 0.0625 and fast taper 0.0875 both outrun the deployed 0.05).
# Mode-dependent rows (D): the uniform strict rows (x_L <= x_R on every mode) DECLINE, because the
# FULL pairing needs the unit above; the uniform +1 rows certify but drop the pre-charge
# requirement. A two-sided pre-charge row (x_L <= x_R and x_R <= x_L + 2) DECLINES, because the
# replayed profile may be in BULK while the deployed cell still precharges. The lambda pin
# matters: with lambda searched on [1, 6] the search takes lambda = 1 first and the CC phase
# certifies only by parking the profile at FULL (the earlier form of this file).
# No pruning (P lost, 2026-10-29, review round 4). Until this date both sides had a latched FAULT
# mode (x < 10, x' = -0.01 x) with declared edges PRECHARGE -> FAULT and BULK -> FAULT, and P rested
# on pruning those two edges. No run takes them: the charging flows rise everywhere below 20 % and
# below 100 %, so a cell in PRECHARGE (x >= 10) or BULK never reaches x < 10; with the edges
# removed RELCERT_NO_PRUNE=1 certifies. SoC is the only state, and a trip a real charge can hit
# (cell overtemperature, overvoltage, a safety time-out) needs a temperature, voltage or clock
# state the profile does not have; such an edge would be taken from the windows next to its
# threshold, so it would be live there and not prunable either. The FAULT mode is removed on both
# sides (a latch no edge enters would be a start-only mode), the pre-charge guard extended to
# [0, 15), and the FAULT unit of the old tight value 2.00 is gone with it (now 1.00).
# Why repositioning is needed (R), and where. Right-only repositioning is used for the lag
# pairings of the BULK_L window only: the replayed profile still in PRECHARGE while the deployed
# cell is in BULK (BULK_L x PRECHARGE_R: the profile precharges alone to 15 % and enters BULK), and
# the replayed profile already tapering while the deployed cell dwells in BULK past 80 %
# (BULK_L x ABSORB_SLOW_R, BULK_L x ABSORB_FAST_R: the profile tapers alone to FULL). Every
# other admissible pairing is a joint segment. RELCERT_NO_REPO=1 DECLINES.
#
# Domain 0 <= x <= 100 both sides (physical: the SoC range); every left mode has a satisfiable
# start (x_L = x_R). The implied contraction atoms x <= 20 (PRECHARGE) and x <= 100 (BULK, tapers)
# are load-bearing (without RELCERT_IMPLIED_CUT and under RELCERT_NO_IMPLIED_CUT=1: DECLINED).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, measured 2026-10-29 on this form): CERTIFIED
# (about 0.6 s); CERTIFIED under RELCERT_NO_CHOICE=1, RELCERT_NO_PRUNE=1, NO_PRUNE+NO_CHOICE,
# RELCERT_NO_LINEAR_CUT=1, RELCERT_OPREGION=1 (every admitted start in some right guard),
# RELCERT_NO_PAIR_STRETCH=1, RELCERT_WELLFORMED_STRICT=1 and with the domain widened 20 %;
# DECLINED under RELCERT_SYNC=1, SYNC+NO_CHOICE, RELCERT_NO_REPO=1, without RELCERT_IMPLIED_CUT,
# RELCERT_NO_IMPLIED_CUT=1 and RELCERT_NO_CUT=1.
# Covers: lambda = 5/4 in every left mode, budget 3 (three replayed profile decisions per deployed
# decision); right-only repositioning in BULK_L through PRECHARGE_R (to BULK) and through the two
# tapers (to FULL); joint steps whose profile BULK segment retains both tapers (branch 2). No edge
# pruned. --handoff 7/7 unsat, non-vacuous (uniform rows decline: D). relcert --wellformed (both
# clauses): PRECHARGE ok (exit->BULK), BULK ok (exit->ABSORB_FAST), ABSORB_SLOW and ABSORB_FAST ok
# (exit->FULL), FULL ok (invariant), 0 UNKNOWN, 0 BLOCKING. The right model changed on 2026-10-29
# (FAULT mode and its two edges removed, pre-charge guard x >= 0 instead of x >= 10; Assumption 1
# proof to be adapted); the left changed in the same way, in its period (batch I9) and in its
# PRECHARGE and ABSORB rates (2026-10-28, the profile's values).
# History: until 2026-10-28 the file raised every deployed rate by 25 % (PRECHARGE 0.25, ABSORB
# 0.0625) and claimed the 2 % bound at equal times (lambda searched on [1, 6], taken at 1): that
# claim is false physically (the deployed leads by up to 7 % in the CC phase) and its certificate
# parked the profile at FULL for every CC-phase pairing (the BULK_L window had no joint segment),
# so its "tightest 1.00" measured the FULL pairing's 100 - 99, not the deployed charger. The
# re-timed one-sided form replaced it; on 2026-10-29 the dead FAULT edges were removed (above).
# Letters: S M R B D I.
[problem]
name = charger_fast_tapers
max_depth = 8
lambda_min = 1.25
lambda_max = 1.25
bound_T = 4.0
[Lsys]
state_vars = [x]
epsilon = 0.012
[Lsys.mode.PRECHARGE]
ode = x' = smt2:(* 0.2 (- 20.0 x));
guard = x >= 0.0 and x < 15.0
evolve = x >= 0.0 and x <= 100.0
next = [BULK, PRECHARGE]
[Lsys.mode.BULK]
ode = x' = smt2:(* 0.125 (- 100.0 x));
guard = x >= 15.0 and x < 80.0
evolve = x >= 0.0 and x <= 100.0
next = [ABSORB, BULK]
[Lsys.mode.ABSORB]
ode = x' = smt2:(* 0.05 (- 100.0 x));
guard = x >= 80.0 and x < 99.0
evolve = x >= 0.0 and x <= 100.0
next = [FULL, ABSORB]
[Lsys.mode.FULL]
ode = x' = smt2:0;
guard = x >= 99.0
evolve = x >= 0.0 and x <= 100.0
next = [FULL]
[Rsys]
state_vars = [x]
epsilon = 0.006
[Rsys.mode.PRECHARGE]
ode = x' = smt2:(* 0.2 (- 20.0 x));
guard = x >= 0.0 and x < 15.0
evolve = x >= 0.0 and x <= 100.0
next = [BULK, PRECHARGE]
[Rsys.mode.BULK]
ode = x' = smt2:(* 0.1 (- 100.0 x));
guard = x >= 15.0 and x < 80.0
evolve = x >= 0.0 and x <= 100.0
next = [ABSORB_SLOW, ABSORB_FAST, BULK]
[Rsys.mode.ABSORB_SLOW]
ode = x' = smt2:(* 0.05 (- 100.0 x));
guard = x >= 80.0 and x < 99.0
evolve = x >= 0.0 and x <= 100.0
next = [FULL, ABSORB_SLOW]
[Rsys.mode.ABSORB_FAST]
ode = x' = smt2:(* 0.07 (- 100.0 x));
guard = x >= 80.0 and x < 99.0
evolve = x >= 0.0 and x <= 100.0
next = [FULL, ABSORB_FAST]
[Rsys.mode.FULL]
ode = x' = smt2:0;
guard = x >= 99.0
evolve = x >= 0.0 and x <= 100.0
next = [FULL]
[relational_invariant]
PRECHARGE = x[l] <= x[r]
BULK = x[l] <= x[r] + 1
ABSORB = x[l] <= x[r] + 1
FULL = x[l] <= x[r] + 1
