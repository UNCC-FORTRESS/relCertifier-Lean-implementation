# lit_girard08_robot: a planar mobile robot (position, velocity and the state of its dynamic tracking
# controller, 6-D) is approximately simulated, with precision 0.4 m, by the 2-D kinematic model
# its planner uses (the example of approximate simulation relations for hybrid systems).
# scenario: abstraction
# mechanisms: X (committed successor subsets: the planner model hops into the robot's heading
#   at the start of every window)
#
# SOURCE. Girard, Julius, Pappas, "Approximate simulation relations for hybrid systems", Discrete
# Event Dynamic Systems 18 (2008) 163-179, Section 5, Eqs. (6)-(8) and Figs. 1-3; robot and
# controller from Fainekos, Girard, Pappas (2007); reused as the planar-robot case study of
# Dupont's thesis (Toulouse 2021, Sec. 7.5.1). Robot y1'' = a (y1 in R^2), dynamic controller
# w' = v, a = v/2 - (101/400)(y1 - w) - y1' (Eq. 7); first-order model y2' = v (Eq. 8). Hybrid
# controller (Fig. 2): six locations, heading v of norm 0.2: (0.2, 0), (0.1r2, -0.1r2),
# (-0.1r2, -0.1r2), (-0.2, 0), (-0.1r2, 0.1r2), (0.1r2, 0.1r2); invariants on y1 = (px, py):
# 1: 0 <= px <= 3, py >= 0; 2: px >= 3, py >= 0; 3: px >= 0, py <= 0; 4: -3 <= px <= 0, py <= 0;
# 5: px <= -3, py <= 0; 6: px <= 0, py >= 0; edges l -> l+1 (cyclic) on px = 3, py = 0, px = 0,
# px = -3, py = 0, px = 0. Approximation (Fig. 3): the same automaton over y2 with invariants and
# guards enlarged by 0.4. With the simulation function V = max(sqrt(|y1 - w|^2 +
# 100 |y1 - w + 2 y1'|^2), 0.4) + |w - y2| (beta = 0.4 in every location), the approximation
# simulates the robot with precision 0.4. Initial y1 in {0} x [4, 6], y1' = 0, w = y1, location 1.
#
# PHYSICAL READING (ours; the source gives no units). A ground robot (m, s) patrols a hexagonal
# loop around a central obstacle at 0.2 m/s. Its planner reasons on the point mass y2' = v (the
# abstraction step of the source, which computes the approximation's reachable set exactly and
# transfers it to the robot: an annulus around the obstacle). The body is a double integrator
# driven by the tracking controller, whose internal reference w moves at the commanded heading.
#
# THIS FILE. Left = robot, right = planner model, one mode per location on both sides, epsilon 1
# on both sides. The robot is written in the coordinates of the source's simulation function:
# e = y1 - w (tracking error), z = e + 2 y1' (filtered error) and w, an invertible linear change of
# variables (y1 = w + e, y1' = (z - e)/2) of Eqs. (6)-(7): ex' = (zx - ex)/2 - vx,
# zx' = -zx/2 - ex/200, wx' = vx (same in y). Its guards are the Fig. 2 invariants on
# y1 = w + e; its evolve domain is the whole plane, one for all six locations (written
# 0.0 <= 1.0, departure (6)): the robot may change location on a guard line and must change
# within the window of at most 1 s after crossing it. The planner's state is y2 = (wx, wy); its
# guards are the Fig. 3 invariants (enlarged by 0.4). Stretch pinned to 1: approximate
# simulation is time-aligned.
#
# CLAIM (every left mode): w_L = y2_R (two inequalities per coordinate) and
# ex^2 + ey^2 + 100 (zx^2 + zy^2) <= 0.16 on the robot; together |y1_L - y2_R| = |e| <= 0.4, the
# source's precision (the quadratic is the square of V's first term, V's second term |w - y2| is
# 0). Tight: 0.1599 DECLINES (on the boundary the quadratic's Lie derivative is -0.16 - 2 e.v,
# zero at |e| = 0.4, |v| = 0.2). Not implied by the domains; every left mode has a satisfiable
# start (e = z = 0, w in the location's invariant), which contains the source's initial set.
#
# Where this file departs from the source.
# (1) Coordinates: the robot in error coordinates (above), the same linear system. In the physical
#   coordinates (px, py, px', py', wx, wy) the claim does not fit the tool's 40 s time budget:
#   ERROR (time budget exceeded, 40 s). The joint segment queries of the diagonal headings
#   dominate (location 1's cover takes 0.2 s, location 2's first queries alone exceed the budget);
#   with the budget raised to 280 s it CERTIFIES in about 128 s (literature draft, every planner
#   edge declared, same admissible starts).
# (2) Location pairing. The source's relation pairs equal locations. Rows are keyed by the left
#   mode and cannot require the planner to be in the paired location, so the cover must also
#   answer planner starts in a location whose enlarged invariant overlaps the robot's (along the
#   axes and at the origin the 0.4-neighbourhoods of locations 1, 3, 4, 6 overlap). With the
#   source's edges (l -> l, l+1) those starts have no edge into the robot's location: DECLINED.
#   Here the planner may switch between any two locations whose enlarged invariants overlap, in
#   both directions, and its guard at a switch is the target's enlarged invariant, not the
#   source's 0.8-wide guard strip (e.g. 2.6 <= px <= 3.4 for 1 -> 2). The certified abstraction
#   is therefore MORE PERMISSIVE than Fig. 3 (extra edges, larger guards): what is certified is
#   weaker than the source's statement, though the planner model is still a 0.4-simulation of
#   the robot, and the source's Fig. 3 automaton is a sub-automaton of it. Edges: 1 -> 1,2,3,4,6;
#   2 -> 1,2,3; 3 -> 1,2,3,4,6; 4 -> 1,3,4,5,6; 5 -> 4,5,6; 6 -> 1,3,4,5,6.
# (3) Planner invariants tested at window starts only: one evolve domain shared by all planner
#   modes, the whole plane (written 0.0 <= 1.0); the handoff check refuses per-mode right evolve
#   domains. Inside a joint window the planner copies w_L, which stays within 0.4 of the robot,
#   hence inside the enlarged invariant of the robot's location.
# (4) 0.1 sqrt 2 written 0.1414213 (just below), on both sides; the enlarged invariants are the
#   Fig. 3 half-planes and strips (coordinatewise, containing the Euclidean 0.4-neighbourhoods).
# (5) Sampled location changes for the planner (at window starts, every 1 s at most; it crosses
#   a 0.8-wide guard strip in no less than 4 s).
# (6) Sampled location changes for the robot too (installed 2026-10-27, batch I8). The generic Lean
#   bridge takes one evolve domain per side (Emitted.uniformEvolve in structOK), so the robot's
#   Fig. 2 invariants are its guards, tested when it enters a location, and its evolve domain is
#   the whole plane: its supervisor reads the position at least once per second, and within a
#   window the reference w runs at most 0.2 m past a guard line. With the source's per-location
#   evolve domains (evolve = guard, the design file) every verdict, the cover and the tight 0.16
#   are the same (measured), but no bridge instance can be stated for that file.
#
