# lit_nahs25_salt_tank: a brine-mixing tank whose salt sensor is under a bounded attack reaches
# only salt levels the genuine tank also reaches: the forward simulation distance 0 of measuring
# robustness of cyber-physical systems under sensor attacks (the source's Def. 8 value).
# scenario: sensor-attack
# mechanisms: W (the genuine tank waits, stretch 0, while the attacked Off holds its level; the
#   file without `stutter = true` DECLINES at the band 0)
#
# SOURCE. Xiang, Lanotte, Tini, Chong, Merro, "Measuring robustness in cyber-physical systems
# under sensor attacks", Nonlinear Analysis: Hybrid Systems 56 (2025) (arXiv 2403.05829), Sec. 7,
# Fig. 7 (model), Figs. 8-13 (proof of the forward distance) and Def. 8 (forward simulation
# distance); the same tank is the forall-exists case study of Xiang and Chong, "Extending dynamic
# logics with first-class relational reasoning" (NFM 2025, Sec. 5). A tank of xL = 100 gal holds
# xp lb of salt; brine of 1/4 lb/gal enters at r gal/min and the stirred mixture drains at r:
# xp' = r/4 - r xp/xL, t' = 1 & t <= eps, eps = 1 (min). Controller xs := xp; (?xs >= 25;
# r := 10) or (?xs < 25; r := 0). Pre xp = 50; safety xp >= 20. Bounded sensor attack:
# xs := *; ?(xp - 3 <= xs <= xp + 3). Def. 8: attacked(P) and P are at forward distance d on
# H = {xp} w.r.t. xp = 50 when for every state the attacked tank reaches there is a state the
# genuine tank reaches with |xp - xp1| <= d. From xp = 50 both tanks reach exactly (25, 50] (the
# attacked Off only holds a level already reached), so the Def. 8 value is 0. The source states
# d = 3, the value of its run-matched proof (the run-wise invariant (25 < xp < 28 and
# 25 < xp1 < 28) or (xp = xp1 and xp >= 28), Fig. 8), in which both tanks run each period in
# lock step.
#
# THIS FILE. Left = attacked controller (forall), right = genuine controller (exists), same
# plant, the direction of Def. 8. The attacked reading is projected onto the physical level,
# exactly: On (r = 10) is possible when some reading in [xp - 3, xp + 3] is >= 25, i.e. xp >= 22;
# Off (r = 0) when some reading is < 25, i.e. xp < 28. Genuine: On iff xp >= 25, Off iff
# xp < 25. Flows On xp' = 0.1 (25 - xp) (the source's 10/4 - 10 xp/100, written in set-point
# form), Off xp' = 0. Stretch 1 (lambda_min = lambda_max = 1) plus the opt-in stretch 0
# (`stutter = true`, docs/STUTTER.md): a joint segment at stretch 0 runs the attacked period
# while the genuine tank takes a zero-duration cycle (it waits).
#
# CLAIM (both left modes): xp_L = xp_R (two rows, xp_L <= xp_R + 0 and xp_R <= xp_L + 0),
# xp_L >= 25 and xp_R >= 25. The band 0 is the source's Def. 8 distance on H = {xp}; the lower
# bounds are the closure of those of the source's invariant (both tanks stay above the On
# equilibrium 25; they also give the source's safety xp >= 20). Requirement: whatever level the
# attacked tank reaches, the genuine tank reaches the same level. The pre xp_L = xp_R = 50
# satisfies the rows, so the certified claim implies the source's forward distance 0. Stutter is
# what captures this time-abstract distance: when the attacked tank holds a level (Off, reading
# below 25 while xp is in [25, 28)) where the genuine one would keep draining toward 25, the
# genuine tank waits at the same level (the cover's Off_L pairings are at stretch 0). A stutter
# certificate does not promise that the reference keeps pace with the attacked run: the genuine
# witness may wait for as long as the attacked tank holds. The lock-step reading (no key) is the
# source's run-matched value 3 (TIGHTNESS). Not implied by the domain (none); every left mode has
# a satisfiable start (xp_L = xp_R = 26). The source's second result (backward distance 0,
# Figs. 14-19) is not this file's claim.
#
# TIGHTNESS (measured 2026-10-29, other rows fixed). xp_L <= xp_R + c certifies down to c = 0
# (-0.01 declines; the rows then admit no start), as does the other row xp_R <= xp_L + c'
# (c' = 0; -0.01 declines): the tool gets the source's Def. 8 value exactly. Without the key the
# band 0 DECLINES and the tight c is 3.00 (2.99 declines), the source's run-matched value and the
# exact lock-step supremum from xp = 50 (the attacked tank may turn Off just below 28 while the
# genuine one settles toward 25). Without the lower bounds the band 0 DECLINES (the band alone is
# not inductive, as in the source, whose invariant carries them too).
#
# CAUSE TEST (measured 2026-10-29). The cause of the distance 0 is that the attacked Off holds
# (xp' = 0, r = 0): letting it drift (xp' = 0.1) makes the band 0 DECLINE with the key (and the
# band 3 too). The attack bound b (left guards xp >= 25 - b, xp < 25 + b) does not move the
# value with the key: b = 0.01, 1, 2, 3, 4, 10 all give c = 0 (as Def. 8 does: from xp = 50 the
# reachable sets coincide for every b); without the key the tight c tracks b (0.01, 1.00, 2.00,
# 3.00, 4.00, 10.00, bisected to within 0.05). b = 0 (attack removed,
# left = right): the band 0 certifies with and without the key (without the lower-bound rows,
# which leave the attacked Off, guard xp < 25, without a start).
#
# Where this file departs from the source.
# (1) No evolve domain, as the source's plant (written as the constant atom 0.0 <= 1.0, the same
#   text on every mode of both sides). The first install added xp >= 0; it was dropped 2026-10-28
#   to match the source, with every verdict unchanged.
# (2) The band and the two lower bounds replace the source's disjunctive invariant; the lower
#   bounds are non-strict (the source writes 25 < xp), a closure the tool needs for its rows and a
#   weaker claim; the claim holds from every related pair, which implies the source's forward
#   distance from xp = 50.
# (3) The source's proof figures write r := 5 in off where Fig. 7 writes r := 0; this file follows
#   Fig. 7. Fig. 7's ctrl also omits the clock reset t := 0 that the source's other figures write;
#   this file assumes the reset (a fresh 1-min window every period).
# (4) Def. 8 relates reachable sets (any genuine state, any time); this file relates the two runs
#   period by period, the genuine tank either running the period in lock step (stretch 1) or
#   waiting (stretch 0). This is a run-wise relation, so it implies the set-based Def. 8 value.
# Assumption 1 holds without a stand-in: both genuine modes admit a full 1-min run from their
# guard (On contracts to 25, Off holds), proved in InstancesV2/WellFormed/LitNahs25SaltTank.lean
# (the right model is unchanged by the key; a zero-duration cycle is covered by Assumption 1 (ii)).
#
# RELATION TO THE RUNNING EXAMPLE (watertank). Not the same benchmark: different plant (salt
# mixing with an on/off brine valve, 2 modes, one equilibrium at 25, vs a water level under
# proportional pumps toward three set points, 3 attacked and 5 reference modes); different attack
# (a bounded reading error anywhere in [-3, 3] at every sample, nondeterministic, vs a constant
# 3 dm offset together with a tampered pump); different mechanisms (watertank S M B with
# stretch 2; here the stutter W at stretch 0). Shared: one tank, a sensor attack of magnitude 3,
# the forward-distance scenario of this source. benchmarks/stutter_demo/salt_tank_stutter is
# this file under another name (the demo of docs/STUTTER.md).
#

# CERTIFIED (about 0.2 s); CERTIFIED under RELCERT_NO_PRUNE=1, RELCERT_NO_CHOICE=1,

# DECLINED under RELCERT_SYNC=1 (lambda = 1 only, which drops the stutter candidate) and
# RELCERT_SYNC=1 RELCERT_NO_CHOICE=1. Cover: On_L at lambda 1 (budget 1) against the genuine On;
# Off_L in a window lamQ = 1, budget 1, both pairings at stretch 0 (RELCERT_DEBUG:
# `[Off_L λ=1] On=fail`, `[Off_L λ=0] On=pass Off=pass`); the genuine On the only admissible
# start (the rows exclude its Off), no choice needed; nothing pruned. Rows identical (--handoff
# vacuous, 4/4). relcert --wellformed: On ok (invariant), Off ok (invariant), 0 UNKNOWN,

[problem]
name = lit_nahs25_salt_tank
max_depth = 8
lambda_min = 1.0
lambda_max = 1.0
bound_T = 40.0
stutter = true

[Lsys]
state_vars = [xp]
epsilon = 1.0

[Lsys.mode.On]
ode = xp' = smt2:(* 0.1 (- 25.0 xp));
guard = xp >= 22.0
evolve = 0.0 <= 1.0
next = [On, Off]

[Lsys.mode.Off]
ode = xp' = smt2:0.0;
guard = xp < 28.0
evolve = 0.0 <= 1.0
next = [On, Off]

[Rsys]
state_vars = [xp]
epsilon = 1.0

[Rsys.mode.On]
ode = xp' = smt2:(* 0.1 (- 25.0 xp));
guard = xp >= 25.0
evolve = 0.0 <= 1.0
next = [On, Off]

[Rsys.mode.Off]
ode = xp' = smt2:0.0;
guard = xp < 25.0
evolve = 0.0 <= 1.0
next = [On, Off]

[relational_invariant]
On = xp[l] <= xp[r] + 0.0 and xp[r] <= xp[l] + 0.0 and xp[l] >= 25.0 and xp[r] >= 25.0
Off = xp[l] <= xp[r] + 0.0 and xp[r] <= xp[l] + 0.0 and xp[l] >= 25.0 and xp[r] >= 25.0
