# platoon3_profiles: a three-follower CACC string on a delayed V2V link against a design model
# with driver-selectable gap profiles.
# scenario: degraded-sensor
# mechanisms: M B P I (multi-step covers, matrix code M2; branching into either non-nominal
#   profile, M3; pruned AEB edges, M4; load-bearing guard cuts, M6)
#
# System. A lead vehicle cruising at constant speed and three automated followers; per link
# i = 1, 2, 3 the gap g_i (m) and the closing rate r_i = v_(i-1) - v_i (m/s), g_i' = r_i: state
# (g1, r1, g2, r2, g3, r3) per side (6-D, linear), time s. Follower i commands
# a_i = a_(i-1) + kp (g_i - c) + kd r_i (CACC with V2V feed-forward; a_0 = 0), so
# r_i' = -kp (g_i - c) - kd r_i; kp = 0.125 /s^2, kd = 0.75 /s, characteristic polynomial
# (s + 0.25)(s + 0.5): over-damped, rational roots rho_1 = 0.25, rho_2 = 0.5.
# Right (design model, epsilon 1 s): the driver selects the gap profile with the time-gap
#   button, CLOSE 28 m, NORMAL 30 m or FAR 32 m (NORMAL <-> CLOSE, NORMAL <-> FAR), applied to all
#   three links; per follower k an AEB fallback BRAKEk (below).
# Left (deployed string, epsilon 2 s): the nominal setting acting on a gap fused with a 40 ms-old
#   V2V position, overstated by 1 m at 25 m/s, so its loops settle at 29 m true; one mode,
#   FOLLOW.
# One cause: the delayed V2V link. The design's profile choice is the envelope the claim is
# stated against: it must hold whichever profile the driver selects.
#
# Guards: the controller's OPERATING RANGE (it stays engaged throughout, under every profile).
# Design CLOSE, NORMAL, FAR (the same guard; the driver may select any profile anywhere in the
# range): 20 <= g_i <= 60 (above the AEB floor, within the radar's range), |r_i| <= 10 (the rated
# closing rate), and the AEB not imminent, 21 <= g_i + 2 r_i <= 59 (the gap projected 2 s ahead
# stays 1 m above the floor and 1 m inside the range; r_i + 0.5 (g_i - c_k) is the decaying slow
# form of profile k, so the guard is forward invariant under every profile and the flow repels at
# g_i = 20 and at g_i = 60). Deployed FOLLOW: 21 <= g_i <= 59, |r_i| <= 10,
# 20 <= g_i + 2 r_i <= 58. The deployed floor 21 m is the AEB floor 20 m plus the 1 m by which the
# rows let the design gap fall below the deployed's: it keeps every design state related to a
# deployed start out of the brake sinks. It is placed for that purpose, with no separate
# physical requirement (the 1 m-shifted floor 19 of platoon3_linkloss, and 20, 20.5, DECLINE).
# The AEB fallback BRAKEk (design model, latched): engages below a 20 m gap whose projected gap
# is also below the floor, g_k < 20 and 0 <= g_k + 2 r_k < 20 (a projected gap below 0 is a
# collision the model does not represent), with the other two links in their operating range;
# follower k then matches its predecessor's speed, r_k' = -0.5 r_k (5 m/s^2 relative braking at
# the rated 10 m/s closing rate), the followers behind it keep the CACC law, and the AEB holds the
# gap it reaches (g_k + 2 r_k is conserved and g_k tends to it) until the driver resumes the
# CACC (not modeled): a sink whose guard is invariant.
#
# Property (derived; Delta = L - R, e_i = Delta g_i + 1 the deviation from the deployed's 1 m
# offset against NORMAL), for every link:
#   Delta r_i + rho_j e_i in [-2 rho_j, 2 rho_j] (j = 1, 2) and |e_i| <= 2,
# i.e. g_i^R - 3 <= g_i^L <= g_i^R + 1 whichever profile the driver selects. Against a profile
# with set point c_k the forms Q_j = Delta r_i + rho_j e_i obey
# Q_j' = -rho_(3-j) (Q_j - rho_j (30 - c_k)): they contract toward 0 (NORMAL) or +-2 rho_j
# (CLOSE, FAR), so [-2 rho_j, 2 rho_j] is the tightest box invariant under all three, and
# |e_i| <= 2 is stratified on the proven Q rows. The constant 2 m is the profiles' set-point
# spread (32 - 30 = 30 - 28); tightest: |e_i| <= 2 certifies, 1.994 declines.
#
# Why pruning is needed (P). Every profile -> BRAKE1, BRAKE2, BRAKE3 (nine edges) is pruned: the
# projected-gap guard conjunct is a kept cut (DI-strict under every profile) and makes the flow
# repel at the AEB threshold (g_k = 20 forces r_k >= 0.5). RELCERT_NO_PRUNE=1 DECLINES (also with
# RELCERT_NO_CHOICE=1): the committed choice does not replace it.
# Why the guard cuts are load-bearing (I). The pruning certificate stands on the kept
# projected-gap conjunct: RELCERT_NO_CUT=1 DECLINES. The widened atoms (linear forms of the
# deployed guard) are kept but not needed: RELCERT_NO_IMPLIED_CUT=1, RELCERT_NO_LINEAR_CUT=1 and a
# run without RELCERT_IMPLIED_CUT certify.
# Multi-step and branching (M, B). Each 2 s left window is matched by 2 design cycles (budget 2);
# the joint step from NORMAL retains CLOSE and FAR, both covering.
#
# Domains (both sides): 0 <= g_i <= 60 m (the radar's range), |r_i| <= 10 m/s (the closing-rate
# range); the certificate stands on no domain bound (every evolve bound widened at once still
# certifies). Coverage: design states outside the operating range and every BRAKEk guard (e.g. a
# gap below 20 m that reopens past 20 m within 2 s) are in no right guard; the design model never
# reaches them, since the operating range is forward invariant under every profile and the sinks
# keep their guards. The left mode has a satisfiable start (the row's offset state inside the
# guards).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated): CERTIFIED; CERTIFIED under RELCERT_SYNC=1 (also
# with RELCERT_NO_CHOICE=1), RELCERT_NO_CHOICE=1, RELCERT_NO_IMPLIED_CUT=1,
# RELCERT_NO_LINEAR_CUT=1, RELCERT_OPREGION=1 and without RELCERT_IMPLIED_CUT; DECLINED under
# RELCERT_NO_PRUNE=1 (also with RELCERT_NO_CHOICE=1) and RELCERT_NO_CUT=1 (the NO_PRUNE runs take
# about 36 s; under heavy load they can hit the tool's time budget, ERROR). Cover: FOLLOW at
# lambda 1 (both sides run the same gains), budget 2, admissible starts NORMAL, CLOSE, FAR; branch
# 2; nine pruned edges. One left mode (--handoff 1/1 vacuous). relcert --wellformed: NORMAL,
# CLOSE, FAR, BRAKE1, BRAKE2, BRAKE3 ok (invariant). Units m, m/s, s.
