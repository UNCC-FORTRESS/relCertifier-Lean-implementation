# quad_light_airframe_20: quadrotor climb with quadratic drag, deployed airframe 20 % lighter than
# the reference model.
# scenario: model-refinement
# mechanisms: S M (time stretch lambda = 7/4 needed, RELCERT_SYNC=1 declines; multi-step cover,
#   matrix codes M1 M2)
#
# System. Climb-rate dynamics with quadratic aerodynamic drag: w' = a - c w^2, w = climb rate
# (m/s), a = net specific thrust (m/s^2), c = drag per unit mass (1/m); no motor lag (the lagged
# pair is quad_light_lag).
#   Right (reference model): a = 4, c = 1, terminal climb rate 2 m/s; plus the autopilot's
#     climb-rate LIMITER above 3 m/s (motor command cut, w' = -2 w), which hands back to CLIMB
#     once w <= 3 (LIMIT -> CLIMB declared).
#   Left (deployed): the airframe is 20 % lighter than the reference model assumed (payload
#     released): the same motor thrust gives T/m_L = 1.25 T/m, so a_L = 1.25 (4 + 9.81) - 9.81 =
#     7.45 (g = 9.81) and c_L = 1.25 c = 1.25; terminal climb rate 2.44 m/s.
# One cause: the airframe mass.
#
# Property: w_L <= w_R + 1 and w_R <= w_L + 0.5 (the deployed never climbs more than 1 m/s faster
# than the reference, and the reference never more than 0.5 m/s faster than the deployed). The
# two constants are round stated tolerances of this family, not derived from an external limit.
# Tightest (bisection to 0.01, one conjunct at a time, the other at its file value): the first
# certifies down to 0.60 (0.59 declines); the second down to 0 (w_R <= w_L; -0.01 declines).
# Not implied by the domains.
#
# Why the stretch is needed (S). The deployed loop is faster: with lambda <= 3/2 the first
# conjunct fails at low climb rates (lambda_max = 1.5 DECLINES); the cover uses lambda = 7/4,
# budget ceil(7/4 * 2 / 1) = 4 right cycles per left window (M).
# Fallback. CLIMB never reaches the limiter (at w = 3 drag wins, w' = -5 < 0), so CLIMB -> LIMIT
# is pruned by a non-connection certificate; LIMIT is no admissible start (w_L <= 2.5 and
# w_R <= w_L + 0.5 exclude w_R > 3). Pruning and the committed choice each close this fallback:
# RELCERT_NO_PRUNE=1 alone certifies, only RELCERT_NO_PRUNE=1 RELCERT_NO_CHOICE=1 declines (no P).
#
# Guards. Left CLIMB 0 <= w <= 2.5 (a climb from hover or a slow climb; forward invariant,
# w' < 0 at 2.5). Right CLIMB 0 <= w <= 3 (the climb controller's operating range up to the
# limiter threshold, forward invariant: w' = 4 - w^2 < 0 at 3, > 0 at 0), LIMIT 3 < w: the right
# guards partition the domain (no gap). The limiter's own flow decays the climb rate below its
# guard within one control period (from 3.1 the 1 s run ends at 3.1 e^-2 = 0.42), so it hands
# back to CLIMB (relcert --wellformed: CLIMB ok (invariant), LIMIT ok (exit->CLIMB)).
# Domains: 0 <= w <= 3.5 m/s both sides (climb only, the rated maximum climb rate). The left
# mode has a satisfiable start (w_L = w_R).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated): CERTIFIED; CERTIFIED under RELCERT_NO_CHOICE=1,
# RELCERT_NO_PRUNE=1, RELCERT_NO_CUT=1, without RELCERT_IMPLIED_CUT, NO_IMPLIED_CUT, NO_LINEAR_CUT
# and the operating region; DECLINED under RELCERT_SYNC=1, SYNC+NO_CHOICE and NO_PRUNE+NO_CHOICE.
# Cover: lambda = 7/4, budget 4, admissible start CLIMB, pruned CLIMB -> LIMIT; --handoff 1/1
# vacuous. Units m/s, m/s^2, s.
[problem]
name = quad_light_airframe_20
max_depth = 8
lambda_min = 1.0
lambda_max = 6.0
bound_T = 4.0
[Lsys]
state_vars = [w]
epsilon = 2.0
[Lsys.mode.CLIMB]
ode = w' = smt2:(- 7.45 (* 1.25 (* w w)));
guard = w >= 0.0 and w <= 2.5
evolve = w >= 0.0 and w <= 3.5
next = [CLIMB]
[Rsys]
state_vars = [w]
epsilon = 1.0
[Rsys.mode.CLIMB]
ode = w' = smt2:(- 4.0 (* w w));
guard = w >= 0.0 and w <= 3.0
evolve = w >= 0.0 and w <= 3.5
next = [CLIMB, LIMIT]
[Rsys.mode.LIMIT]
ode = w' = smt2:(* -2.0 w);
guard = w > 3.0
evolve = w >= 0.0 and w <= 3.5
next = [LIMIT, CLIMB]
[relational_invariant]
CLIMB = smt2:(and (<= L_w (+ R_w 1.0)) (<= R_w (+ L_w 0.5)))
