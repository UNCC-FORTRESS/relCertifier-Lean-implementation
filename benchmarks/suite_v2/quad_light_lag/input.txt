# quad_light_lag: the 20 %-lighter quadrotor against the nominal airframe, both with the same
# motor thrust lag.
# scenario: model-refinement
# mechanisms: S M (time stretch lambda = 7/4 needed, RELCERT_SYNC=1 declines; multi-step cover,
#   matrix codes M1 M2)
#
# System. Climb rate w (m/s) and net specific thrust a (m/s^2); quadratic drag, w' = a - c w^2.
# The motors realise the climb command through a first-order lag of 0.2 s, a' = 5 (a_cmd - a).
#   Left (deployed): the airframe is 20 % lighter than the reference model assumed (payload
#     released), the same motors and command: thrust-to-mass x 1/0.8 = 1.25, a_cmd = 1.25 (4 +
#     9.81) - 9.81 = 7.45, c = 1.25 (terminal climb rate 2.44 m/s); the airframe of
#     quad_light_airframe_20, now with its motor lag.
#   Right (reference): the nominal airframe with the same lag: a_cmd = 4, c = 1 (terminal 2 m/s).
# The airframe mass is the only difference.
#
# Property. The climb-rate tolerance of this family (a round stated tolerance, as in
# quad_light_airframe_20, not derived from an external limit): the deployed never climbs more
# than 1 m/s faster than the reference, w_L <= w_R + 1. Tightest: 0.53 (0.52 declines).
# Strengthening row (exact, no constant): a_L <= 1.8625 a_R, i.e.
# a_L / 7.45 <= a_R / 4: the deployed has realised no larger fraction of its climb command than
# the reference. Both thrust deficits 7.45 - a_L and 4 - a_R decay at 5 /s; at any stretch
# lambda >= 1 the reference's decays faster, so the row is kept once it holds at the start (it
# holds with equality for a climb started from hover, a = 0 on both sides). Without it the
# climb-rate row needs w_L <= w_R + 2.45 (2.44 declines): the lighter airframe's thrust would be
# unconstrained.
#
# Guards. Left: a climb starts from hover or a slow climb, 0 <= w <= 2.5 m/s, forward invariant
# (w' < 0 at 2.5). Right: the whole climb envelope 0 <= w <= 3.5 (every left state has a right
# mode to start in). No limiter mode on this rung. Domains: w in [0, 3.5] m/s both sides (climb
# only, the rated maximum climb rate); thrust a in [0, 7.45] left, [0, 4] right (hover to the
# climb command; forward invariant: a' >= 0 below the command). Every box is forward invariant
# (relcert --wellformed CLIMB ok (invariant)); the left mode has a satisfiable start (hover).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated): CERTIFIED; DECLINED under RELCERT_SYNC=1 (and
# SYNC+NO_CHOICE); CERTIFIED under NO_PRUNE, NO_CHOICE, NO_PRUNE+NO_CHOICE, without
# RELCERT_IMPLIED_CUT, NO_IMPLIED_CUT, NO_LINEAR_CUT, NO_CUT, the operating region and
# RELCERT_WELLFORMED_STRICT=1.
# Cover: lambda = 7/4 (the lag-free rung's stretch), budget ceil(7/4 * 2 / 1) = 4, nothing pruned;
# --handoff 1/1 vacuous. Units m/s, m/s^2, s.
[problem]
name = quad_light_lag
max_depth = 8
lambda_min = 1.0
lambda_max = 6.0
bound_T = 4.0
[Lsys]
state_vars = [w, a]
epsilon = 2.0
[Lsys.mode.CLIMB]
ode = w' = smt2:(- a (* 1.25 (* w w))); a' = smt2:(* 5.0 (- 7.45 a));
guard = w >= 0.0 and w <= 2.5 and a >= 0.0 and a <= 7.45
evolve = w >= 0.0 and w <= 3.5 and a >= 0.0 and a <= 7.45
next = [CLIMB]
[Rsys]
state_vars = [w, a]
epsilon = 1.0
[Rsys.mode.CLIMB]
ode = w' = smt2:(- a (* w w)); a' = smt2:(* 5.0 (- 4.0 a));
guard = w >= 0.0 and w <= 3.5 and a >= 0.0 and a <= 4.0
evolve = w >= 0.0 and w <= 3.5 and a >= 0.0 and a <= 4.0
next = [CLIMB]
[relational_invariant]
CLIMB = smt2:(and (<= L_w (+ R_w 1.0)) (<= L_a (* 1.8625 R_a)))
