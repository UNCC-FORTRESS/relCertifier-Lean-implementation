# quad_light_profiles: the 20 %-lighter quadrotor flying the plan's NORMAL climb against a
# reference model with pilot-selectable climb profiles; real-time altitude conformance to the
# reference's SPORT profile.
# scenario: model-refinement
# mechanisms: X (committed existential choice: at each window start the reference commits the
#   pilot's selection to SPORT, which is not the deployed's own profile; RELCERT_NO_CHOICE=1
#   declines). No S, M, B: the claim is synchronous (lambda fixed to 1), one segment per window.
#
# Round A (2026-10-26): the previous file claimed conformance to NORMAL at the time scaling 6/5
# (letters S M B X) with a profile graph lacking ECO <-> SPORT; with that graph completed the
# synchronous claim below certifies under RELCERT_SYNC=1, so S was a choice of claim, not forced
# by the cause. This file adopts the complete graph and the synchronous claim; the time-scaled
# reading of the same airframe pair stays in quad_light_airframe_20 (in benchmarks/reserve/ since
# 2026-10-27, batch I7; quad_light_lag keeps the time-scaled claim in the suite).
#
# System. The climb segment of quad_light_airframe_20 (same airframe numbers): altitude h (m),
# climb rate w (m/s), m w' = T - m g - k w, h' = w, g = 9.81 m/s^2.
#   Right (reference model of the autopilot): the pilot may select the climb profile in flight;
#     the selection sets the thrust ratio and any profile may follow any profile at the next 1 s
#     control interval (complete graph: NORMAL, ECO, SPORT each list all three). k/m_R = 4.905 /s:
#       NORMAL T = 2 m_R g:   w' = 9.81 - 4.905 w    (terminal 2.0 m/s)
#       ECO    90 % thrust:   w' = 7.848 - 4.905 w   (terminal 1.6 m/s)
#       SPORT  110 % thrust:  w' = 11.772 - 4.905 w  (terminal 2.4 m/s)
#   Left (deployed): the flight plan's NORMAL profile on the airframe 20 % lighter than the
#     reference model assumed (T/m and k/m both x 1.25): w' = 14.715 - 6.13125 w (terminal
#     2.4 m/s), as in quad_light_airframe_20.
# One cause: the airframe mass. The lighter airframe at NORMAL thrust has the terminal climb rate
# of the reference's SPORT profile ((2 - m_L/m_R) x 2.0 = 2.4 m/s); it differs from SPORT only in
# its faster transient (time constant 1/6.13125 s instead of 1/4.905 s).
#
# Requirement: altitude conformance in real time to the PX4 default multicopter altitude
# acceptance radius NAV_MC_ALT_RAD = 0.8 m: at every time t the deployed's altitude is within
# 0.8 m of the altitude of some reference run (the pilot's selections resolved existentially).
# lambda_min = lambda_max = 1 (real time, the claim compares equal times).
#   rows 1, 2 (the requirement): h_R - h_L <= 0.8 and h_L - h_R <= 0.8.
#   row 3 (strengthening): Psi_S <= 0.8, with
#     Psi_S = (h_L - h_R) + (w_L - 2.4)/6.13125 - (w_R - 2.4)/4.905 (times 6.13125 in the file),
#     the steady-climb altitude gap against SPORT; conserved exactly in real time when the
#     reference flies SPORT (Psi_S' = 0).
#   row 4 (strengthening): w_R <= w_L: the lighter airframe accelerates at least as hard as SPORT
#     at every equal climb rate w <= 2.4. Under row 4, h_L - h_R <= Psi_S (row 3 gives row 2) and
#     h_L - h_R never decreases (row 1 holds from any start that satisfies it).
#   Needed: dropping row 3 or row 4 DECLINES; a lower Psi_S row is not needed (not in the file).
# Tightest (measured): the rows are homogeneous and certify at every common constant c >= 0 for
# rows 1 to 3; the hover start (h_L = h_R, w_L = w_R = 0) is related iff c >= Psi_S(hover) =
# 0.0979 m (the deployed leads SPORT by at most 9.8 cm), so the 0.8 m radius leaves 0.70 m.
# Not implied by the domains.
#
# Cause dependence (measured, rows as in the file unless stated): no mass change (left = the
# reference airframe at NORMAL): DECLINED; that left satisfies the exact claim h_L = h_R,
# w_L = w_R against NORMAL instead (CERTIFIED; NO_CHOICE declines). 25 % lighter (terminal
# 2.5 m/s, above every profile): DECLINED, and the requirement is false (the deployed climbs away
# from every reference run at >= 0.1 m/s). 15 % lighter (terminal 2.3 m/s, between NORMAL and
# SPORT): DECLINED (no single profile matches; a reference alternating profiles is not searched
# by the per-window cover). The previous graph without ECO <-> SPORT: DECLINED (ECO cannot reach
# SPORT in one hop).
# Existential choice (X). When the reference starts in NORMAL or ECO the cover hops into SPORT
# (choice hops NORMAL -> SPORT, ECO -> SPORT) and runs one joint segment; against NORMAL or ECO
# row 3 drifts. RELCERT_NO_CHOICE=1 DECLINES. The hop target is the reference profile the
# degraded airframe behaves like, not a copy of the deployed's mode.
#
# Guards and domains. Left CLIMB guard = evolve: h >= 0, 0 <= w <= 2.4 (the deployed's climb
# envelope, forward invariant). Right NORMAL, ECO, SPORT guard = evolve: h >= 0, 0 <= w <= 2.4,
# the envelope of the strongest profile (SPORT), forward invariant in every profile (each
# terminal rate <= 2.4): the right guards coincide, no coverage gap. Altitude unbounded above
# (climb segments of any length); the left mode has a satisfiable start (hover). The 3 m/s
# climb-rate limiter lies above every envelope and never engages: not modeled. Control interval
# 1 s on both sides.
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, measured 2026-10-26 with the round-A binary):
# CERTIFIED (about 0.3 s); CERTIFIED under RELCERT_SYNC=1, RELCERT_NO_PRUNE=1, without
# RELCERT_IMPLIED_CUT, RELCERT_NO_IMPLIED_CUT=1, RELCERT_NO_LINEAR_CUT=1, RELCERT_NO_CUT=1,
# RELCERT_NO_PAIR_STRETCH=1, RELCERT_WELLFORMED_STRICT=1 and RELCERT_OPREGION=1 (every admitted
# start in some right guard); DECLINED under RELCERT_NO_CHOICE=1, NO_PRUNE+NO_CHOICE and
# SYNC+NO_CHOICE. Cover: CLIMB by choice at lambda 1, budget 1, admissible NORMAL, ECO, SPORT,
# hops NORMAL -> SPORT and ECO -> SPORT, nothing pruned. --handoff 1/1 vacuous (one left mode).
# relcert --wellformed: NORMAL, ECO, SPORT ok (invariant), 0 UNKNOWN. Units m, m/s, m/s^2, s.
[problem]
name = quad_light_profiles
max_depth = 8
lambda_min = 1.0
lambda_max = 1.0
bound_T = 4.0
[Lsys]
state_vars = [h, w]
epsilon = 1.0
[Lsys.mode.CLIMB]
ode = h' = w; w' = smt2:(- 14.715 (* 6.13125 w));
guard = h >= 0.0 and w >= 0.0 and w <= 2.4
evolve = h >= 0.0 and w >= 0.0 and w <= 2.4
next = [CLIMB]
[Rsys]
state_vars = [h, w]
epsilon = 1.0
[Rsys.mode.NORMAL]
ode = h' = w; w' = smt2:(- 9.81 (* 4.905 w));
guard = h >= 0.0 and w >= 0.0 and w <= 2.4
evolve = h >= 0.0 and w >= 0.0 and w <= 2.4
next = [NORMAL, ECO, SPORT]
[Rsys.mode.ECO]
ode = h' = w; w' = smt2:(- 7.848 (* 4.905 w));
guard = h >= 0.0 and w >= 0.0 and w <= 2.4
evolve = h >= 0.0 and w >= 0.0 and w <= 2.4
next = [ECO, NORMAL, SPORT]
[Rsys.mode.SPORT]
ode = h' = w; w' = smt2:(- 11.772 (* 4.905 w));
guard = h >= 0.0 and w >= 0.0 and w <= 2.4
evolve = h >= 0.0 and w >= 0.0 and w <= 2.4
next = [SPORT, NORMAL, ECO]
[relational_invariant]
CLIMB = smt2:(and (<= (- R_h L_h) 0.8) (<= (- L_h R_h) 0.8) (<= (+ (* 6.13125 (- L_h R_h)) (- L_w (* 1.25 R_w)) 0.6) (* 6.13125 0.8)) (<= R_w L_w))
