# quad_light_profiles: 40 %-lighter quadrotor against a reference autopilot with selectable climb-thrust profiles.
# scenario: model-refinement
# mechanisms: S M B X (time stretch lambda = 3; multi-step cover with joint steps from NORMAL
#   and SPORT retaining two profiles; committed existential choice of the reference's profile,
#   matrix codes M1 M2 M3)
#
# System. Climb rate w (m/s) with quadratic drag, w' = a - c w^2 (a net specific thrust m/s^2,
# c drag per unit mass 1/m). Reference (right): the autopilot's climb profiles, selectable in
# flight from NORMAL to either neighbour and back: NORMAL a = 4 (terminal 2.0 m/s), ECO a = 3.6
# (90 % thrust, terminal 1.90), SPORT a = 4.4 (110 %, terminal 2.10), c = 1; plus the
# climb-rate LIMITER above 3.2 m/s (motor command cut, w' = -2 w; it hands back to NORMAL once
# w <= 3.2). Deployed (left): the same motors and NORMAL command on an airframe 40 % lighter
# than the reference model assumed: thrust-to-mass x 1/0.6 = 5/3, so a_L = (5/3)(4 + 9.81) -
# 9.81 = 39.62/3 = 13.21 and c_L = 5/3 (terminal 2.81 m/s). (Before 2026-10-26 the file used the
# factor 1.4, a 29 % lighter airframe, under the "40 %" label.) One cause: the airframe mass.
#
# Guards. Left CLIMB: 0 <= w <= 3.2, the climb controller's operating range, the same range as
# the reference's climb modes (up to the limiter threshold; it was 2.2 m/s, a ceiling placed so
# that the reference's LIMIT was no admissible start). Right climb modes 0 <= w <= 3.2, LIMIT
# w > 3.2: the right guards partition the domain. Physical domain 0 <= w <= 3.5 m/s both sides
# (climb only, the rated maximum climb rate). Every climb guard is forward invariant (drag wins
# at 3.2 in every profile and in the deployed); relcert --wellformed: NORMAL, ECO, SPORT ok
# (invariant), LIMIT ok (exit->NORMAL).
#
# Property: w_L <= w_R + 1 and w_R <= w_L.
#   w_L <= w_R + 1: requirement (the climb-rate tolerance of this family, as in
#     quad_light_airframe_20 and quad_light_lag): the lighter airframe never climbs more than
#     1 m/s faster than the reference profile. Tightest 0.91 (0.90 declines).
#   w_R <= w_L: the reference profile never climbs faster than the lighter airframe (at the
#     matched, stretched time). Constant 0 so that a common start from hover (w_L = w_R = 0) is
#     related; the row certifies down to w_R <= w_L - 0.56 (-0.57 declines), which would
#     exclude that start.
# Fallback placed honestly: w_R <= w_L <= 3.2 keeps the reference out of LIMIT at every start,
# and NORMAL / ECO / SPORT -> LIMIT are pruned (drag wins at 3.2); RELCERT_NO_PRUNE=1 CERTIFIES
# (the second row already excludes LIMIT along the cover).
# Existential choice (X). ECO is too slow for the first row; when the reference starts in ECO
# the cover commits the pilot's selection to NORMAL (choice hops ECO -> NORMAL), and
# RELCERT_NO_CHOICE=1 DECLINES. The matrix replays the choice cover with the extended checker
# (decideCoveredX: hop ECO -> NORMAL, then joint steps from NORMAL and SPORT, branch 2).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated): CERTIFIED; CERTIFIED under NO_PRUNE, without
# RELCERT_IMPLIED_CUT, NO_IMPLIED_CUT, NO_LINEAR_CUT, NO_CUT, RELCERT_WELLFORMED_STRICT=1;
# DECLINED under RELCERT_SYNC=1, NO_CHOICE, NO_PRUNE+NO_CHOICE and SYNC+NO_CHOICE. Cover: CLIMB
# by choice at lambda = 3 (per pairing: NORMAL 3, SPORT 11/4), budget ceil(3 * 2 / 1) = 6.
# --handoff 1/1 vacuous. Units m/s, m/s^2, s.
[problem]
name = quad_light_profiles
max_depth = 8
lambda_min = 1.0
lambda_max = 6.0
bound_T = 4.0
[Lsys]
state_vars = [w]
epsilon = 2.0
[Lsys.mode.CLIMB]
ode = w' = smt2:(- (/ 39.62 3.0) (* (/ 5.0 3.0) (* w w)));
guard = w >= 0.0 and w <= 3.2
evolve = w >= 0.0 and w <= 3.5
next = [CLIMB]
[Rsys]
state_vars = [w]
epsilon = 1.0
[Rsys.mode.NORMAL]
ode = w' = smt2:(- 4.0 (* w w));
guard = w >= 0.0 and w <= 3.2
evolve = w >= 0.0 and w <= 3.5
next = [NORMAL, ECO, SPORT, LIMIT]
[Rsys.mode.ECO]
ode = w' = smt2:(- 3.6 (* w w));
guard = w >= 0.0 and w <= 3.2
evolve = w >= 0.0 and w <= 3.5
next = [ECO, NORMAL, LIMIT]
[Rsys.mode.SPORT]
ode = w' = smt2:(- 4.4 (* w w));
guard = w >= 0.0 and w <= 3.2
evolve = w >= 0.0 and w <= 3.5
next = [SPORT, NORMAL, LIMIT]
[Rsys.mode.LIMIT]
ode = w' = smt2:(* -2.0 w);
guard = w > 3.2
evolve = w >= 0.0 and w <= 3.5
next = [LIMIT, NORMAL]
[relational_invariant]
CLIMB = smt2:(and (<= L_w (+ R_w 1.0)) (<= R_w L_w))
