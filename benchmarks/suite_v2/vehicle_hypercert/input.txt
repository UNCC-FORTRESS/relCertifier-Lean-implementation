# vehicle_hypercert: initial-state opacity of the vehicle case study of Murali, Falah, Trivedi and
# Zamani (HyperCertificates, arXiv 2605.00752, Sec. 9.2), in continuous time: the observer sees
# the velocity, the secret is the start position.
# scenario: opacity
# mechanisms: X (committed successor subsets: the partner run copies the secret run's
#   acceleration at the start of every window)
#
# SOURCE. State (s, v, w): position s in [0, 8], velocity v in [0, 0.6], acceleration w chosen
# each step from {-0.04, -0.02, 0, 0.02, 0.04}; step s' = s + v + w/2, v' = v + w. Initial set
# X0 = [0, 8] x [0, 0.6] x W, secret set Xs = [0, 1] x [0, 0.6] x W. The observer sees v with
# precision delta = 0.01. Property (initial-state opacity): for every run from a secret state
# there is a run from a non-secret initial state whose observations stay delta-close forever.
# The source gives no units; this file reads them as m, m/s and m/s^2.
#
# THIS FILE. Both sides are the vehicle, state (s, v): one mode per acceleration (Am4, Am2, A0,
# Ap2, Ap4 = -0.04, -0.02, 0, 0.02, 0.04), s' = v, v' = w held for the 1 s period (epsilon 1 on
# both sides): the source's step is the exact 1 s sampling of this flow. The left run is the
# secret run, the right run its non-secret partner. Guards keep the velocity in [0, 0.6] over one
# period (Am4 needs v >= 0.04, Ap4 needs v <= 0.56, ...); A0 is enabled everywhere, so the right
# guards cover the domain. Stretch pinned to 1 (lambda in [1, 1]): opacity compares the
# observations instant by instant.
#
# Rows (every left mode): v_L = v_R and s_R = s_L + 2. The first row is the observation (equal
# velocities, which implies the source's delta-closeness); the second is the start offset: a
# secret start s_L in [0, 1] is paired with the non-secret start s_L + 2 in [2, 3], inside the
# source's X0 and outside Xs, with the same velocity. Theorem 3 from these rows is the opacity
# statement: from every such pair, whatever the secret run does, the partner (2 m ahead) keeps
# the same velocity forever. Any offset in (1, 7] maps Xs into X0 \ Xs (1.01 and 7 also certify).
# Not implied by the domains. Every left mode has a satisfiable start (s_L = 0.5, s_R = 2.5,
# v_L = v_R = 0.3).
#
# The claim depends on the cause. The secret cannot reach the observable because the velocity
# never reads the position; with a position-dependent rule (Ap2 and Ap4 allowed only for
# s <= 4, on both sides, a speed zone) the same claim DECLINES (also with s_R >= s_L + 2): the
# partner, being ahead, loses the right to accelerate first, a genuine leak.
#
# Where this file departs from the source.
# (1) Position range. The domain is s >= 0 with no upper bound (forward invariant: v >= 0); the
#   source's 8 enters only as the start range X0 that the offset row respects. The range cannot
#   be kept as an evolve bound s <= 8: (a) the right model would block at s = 8 with v > 0 (no
#   run of a full control interval, so Assumption 1 is false), so it would not lift to a
#   theorem; the default run still CERTIFIES such a file, and the strict Assumption 1 gate
#   (relcert --wellformed, both clauses since 2026-10-26) reports all five modes BLOCKING and
#   DECLINES it under RELCERT_WELLFORMED_STRICT=1 (benchmarks/negative_wellformed/
#   vehicle_hypercert_s8; until then the check covered the successor half only and reported
#   the modes ok); (b) read with every run
#   confined to [0, 8] the property is false: the secret run from s = 0 at v = 0.6 that cruises
#   (A0) for 5 s and brakes (Am4) for 15 s comes to rest at s = 7.5 and stays in [0, 8], and a
#   partner whose velocity stays within 0.01 of it covers at least 7.5 - 0.01 x 20 = 7.3 m, so
#   it starts below 0.7, a secret state. Its Sec. 9.2 does not say how a successor outside
#   [0, 8] is treated, but its formalism does: Sec. 2.2 confines runs to the state set
#   (f : X -> 2^X, runs in X^omega, with X = [0, 8] x [0, 0.6] x W here), so the literal reading
#   is the formal one. This file departs from it and takes the reading in which the position may
#   grow past 8, with [0, 8] the start range only; under that reading the opacity claim holds and
#   is certified here.
# (2) Exact observation. The rows ask v_L = v_R, stronger than delta-closeness. A row
#   |v_L - v_R| <= 0.01 is not inductive at the velocity limits (a partner 0.01 faster than a
#   secret run in Ap4 at v = 0.56 cannot use Ap4) and DECLINES; equal velocities are what the
#   witness keeps.
# (3) Continuous time. The secret run may switch acceleration after less than a full period
#   (a left window is at most 1 s), which the source's discrete step does not allow; the
#   partner copies each switch.
#
# Why committed choice is needed (X). At the start of each window the partner hops into the
# secret run's acceleration and the two velocities move together. Without the choice
# (RELCERT_NO_CHOICE=1) the partner must flow on in whatever admissible acceleration it holds,
# and the velocities separate: DECLINED. No right-only segment is used (the previous,
# velocity-only version of this file used one through A0).
#
# Letter window: X at every offset tested (1.01, 2 and 7: RELCERT_NO_CHOICE=1 declines each).
#
# Verdicts (RELCERT_IMPLIED_CUT=1 unless stated, measured 2026-10-26, re-measured 2026-10-28 on
# branch benchmark-fixes, unchanged): CERTIFIED (about 1 s); CERTIFIED under RELCERT_SYNC=1,
# RELCERT_NO_PRUNE=1, RELCERT_NO_CUT=1, RELCERT_NO_IMPLIED_CUT=1, RELCERT_NO_LINEAR_CUT=1,
# RELCERT_NO_REPO=1, RELCERT_OPREGION=1, RELCERT_NO_PAIR_STRETCH=1,
# RELCERT_WELLFORMED_STRICT=1 and without RELCERT_IMPLIED_CUT; DECLINED under RELCERT_NO_CHOICE=1
# (also with RELCERT_SYNC=1 and with RELCERT_NO_PRUNE=1). Cover: every left mode at lambda 1,
# budget 1, every right mode an admissible start, one hop into the left's acceleration, no
# branching, nothing pruned. Rows identical (--handoff 25/25 vacuous). relcert --wellformed:
# Am4, Am2, Ap2, Ap4 ok (exit), A0 ok (invariant), 0 UNKNOWN.
[problem]
name = vehicle_hypercert
max_depth = 8
lambda_min = 1.0
lambda_max = 1.0
bound_T = 40.0

[Lsys]
state_vars = [s, v]
epsilon = 1.0

[Lsys.mode.Am4]
ode = s' = v; v' = smt2:(- 0.0 0.04);
guard = v >= 0.04 and v <= 0.6
evolve = s >= 0.0 and v >= 0.0 and v <= 0.6
next = [Am4, Am2, A0, Ap2, Ap4]

[Lsys.mode.Am2]
ode = s' = v; v' = smt2:(- 0.0 0.02);
guard = v >= 0.02 and v <= 0.6
evolve = s >= 0.0 and v >= 0.0 and v <= 0.6
next = [Am4, Am2, A0, Ap2, Ap4]

[Lsys.mode.A0]

guard = v >= 0.0 and v <= 0.6
evolve = s >= 0.0 and v >= 0.0 and v <= 0.6
next = [Am4, Am2, A0, Ap2, Ap4]

[Lsys.mode.Ap2]
ode = s' = v; v' = smt2:0.02;
guard = v >= 0.0 and v <= 0.58
evolve = s >= 0.0 and v >= 0.0 and v <= 0.6
next = [Am4, Am2, A0, Ap2, Ap4]

[Lsys.mode.Ap4]

evolve = s >= 0.0 and v >= 0.0 and v <= 0.6
next = [Am4, Am2, A0, Ap2, Ap4]
