# watertank: set-point level controller under a sensor offset and a tampered fill pump.
# scenario: sensor-attack
# mechanisms: M1 M2 M3 M4 M6 M6+
#
# THE PAPER'S RUNNING EXAMPLE (redesigned 2026-10-09, supersedes the fill-speedup
# watertank of the earlier passes; docs/SUITE-REDESIGN.md section 18).
#
# THE PLANT. A tank of capacity 25 (level x in dm, so a 2.5 m tank; time in minutes).
# Every mode is a proportional pump controller that drives the level toward a set point c,
#   x' = k (c - x),   k = 0.3 /min   (a first-order relaxation, time constant ~3.3 min).
# NOMINAL controller (right, the reference design):
#   PumpOff  x < 2           x' = 0               dry-run interlock: below the 2 dm intake
#                                                  the pump is switched off and latched
#                                                  (a sink, PumpOff -> PumpOff only)
#   Low      2 <= x < 10     x' = 0.3 (12.5 - x)  fill toward 12.5
#   Mid      10 <= x < 17    toward 17, in two selectable pump profiles chosen on entry:
#              MidEco          x' = 0.15 (17 - x)   half gain k/2 (energy-saving)
#              MidBoost        x' = 0.3 (17 - x)    full gain k
#   High     x >= 17         x' = 0.3 (17 - x)    regulate (drain) down to 17
# The nominal controller may move between MidEco and MidBoost at any time while in Mid,
# and returns from High into either profile.
#
# THE ATTACK (left, the deployed controller):
#   1. Sensor offset: the level sensor reads 3 dm LOW (x_measured = x - 3), so every
#      threshold and every set point the controller acts on is 3 dm higher in true level:
#        Low  5 <= x < 13   toward 15.5 (= 12.5 + 3)
#        Mid  13 <= x < 20  toward 20   (= 17 + 3), gain k
#        High x >= 20       regulate down to 20
#   2. Pump tamper: the Low pump runs at TWICE the nominal gain, x' = 0.6 (15.5 - x).
#   The deployed controller has a single Mid profile and no dry-run mode: its Low floor
#   5 = 2 + 3 is the nominal intake threshold shifted by the offset.
#
# CLAIM (two rows per mode): |x_L - x_R| <= 3, i.e. x_L <= x_R + 3 and x_R <= x_L + 3 in
# every left mode: the true levels of the deployed and the reference tank never differ
# by more than the sensor offset. The tolerance 3 IS the offset, and it is tight: with
# tolerance 2.9 (both rows) the benchmark is DECLINED (measured). Why it is tight
# (derived from the model): on the boundary x_L = x_R + 3 the deployed Low field is
# 0.6 (15.5 - x_L) = 0.6 (12.5 - x_R), exactly the nominal Low field run at speed
# ratio 2, so the gap is neutral there (zero Lie derivative), not contracting; the same
# holds for Mid against MidEco at ratio 2 and against MidBoost at ratio 1.
#
# DOMAIN: the tank capacity, 0 <= x <= 25, identical in every mode on both sides. No
# certificate stands on it: widened to x <= 60 (and to -60 <= x <= 60) the benchmark
# still CERTIFIES (measured).
#
# MEASURED (relcert, RELCERT_IMPLIED_CUT=1; epsilon_L = epsilon_R = 1 min, lambda grid
# [1, 6]; counter-runs as in docs/SUITE-REDESIGN.md section 2):
#   * CERTIFIED with no reposition of any kind: the replayed cover derivation consists
#     of joint segments only (every left/right pair it visits is a joint segment; no
#     static and no dynamic right-only step).
#   * Low and Mid certify at lambda = 2 (the speed ratio: the tampered Low pump against
#     the nominal one, and the full-gain deployed Mid against MidEco) with budget 2
#     (two right segments per left window); High at lambda = 1, budget 1.
#   * Branching (M3): a joint step from the nominal Low retains BOTH MidEco and MidBoost, and
#     both cover. MidEco needs lambda = 2, MidBoost already passes at lambda = 1 (the
#     per-lambda segment rows of RELCERT_DEBUG=1: for the deployed Mid, MidEco passes
#     only at lambda = 2, MidBoost at every grid point from 1).
#   * Pruning: Low -> PumpOff is pruned (the nominal Low flow from its entry x >= 2
#     never reaches x < 2). RELCERT_NO_PRUNE=1 DECLINES: the deployed Low window cannot
#     cover a reference latched in PumpOff (its segment fails at every lambda). The
#     deployed floor 5 = 2 + 3 keeps PumpOff out of the admissible starts for the
#     deployed Low.
#   * Cuts: the set-point atoms x <= c are the cuts (deployed Low x <= 15.5, an implied
#     contraction atom; deployed Mid x <= 20, nominal MidEco / MidBoost x <= 17, the
#     closures of the strict guard caps; nominal Low x <= 12.5, implied). RELCERT_NO_CUT=1
#     and RELCERT_NO_IMPLIED_CUT=1 both DECLINE; RELCERT_NO_LINEAR_CUT=1 still CERTIFIES
#     (no linear-form atom is kept).
[problem]
name = watertank
max_depth = 8
lambda_min = 1.0
lambda_max = 6.0
bound_T = 40.0

[Lsys]
state_vars = [x]
epsilon = 1.0

[Lsys.mode.Low]
ode = x' = smt2:(* 0.6 (- 15.5 x));
guard = x >= 5.0 and x < 13.0
evolve = x >= 0.0 and x <= 25.0
next = [Low, Mid]

[Lsys.mode.Mid]
ode = x' = smt2:(* 0.3 (- 20.0 x));
guard = x >= 13.0 and x < 20.0
evolve = x >= 0.0 and x <= 25.0
next = [Mid, High]

[Lsys.mode.High]
ode = x' = smt2:(* 0.3 (- 20.0 x));
guard = x >= 20.0
evolve = x >= 0.0 and x <= 25.0
next = [High, Mid]

[Rsys]
state_vars = [x]
epsilon = 1.0

[Rsys.mode.Low]
ode = x' = smt2:(* 0.3 (- 12.5 x));
guard = x >= 2.0 and x < 10.0
evolve = x >= 0.0 and x <= 25.0
next = [Low, MidEco, MidBoost, PumpOff]

[Rsys.mode.MidEco]
ode = x' = smt2:(* 0.15 (- 17.0 x));
guard = x >= 10.0 and x < 17.0
evolve = x >= 0.0 and x <= 25.0
next = [MidEco, MidBoost, High]

[Rsys.mode.MidBoost]
ode = x' = smt2:(* 0.3 (- 17.0 x));
guard = x >= 10.0 and x < 17.0
evolve = x >= 0.0 and x <= 25.0
next = [MidBoost, MidEco, High]

[Rsys.mode.High]
ode = x' = smt2:(* 0.3 (- 17.0 x));
guard = x >= 17.0
evolve = x >= 0.0 and x <= 25.0
next = [High, MidEco, MidBoost]

[Rsys.mode.PumpOff]
ode = x' = smt2:0.0;
guard = x < 2.0
evolve = x >= 0.0 and x <= 25.0
next = [PumpOff]

[relational_invariant]
Low  = x[l] <= x[r] + 3 and x[r] <= x[l] + 3
Mid  = x[l] <= x[r] + 3 and x[r] <= x[l] + 3
High = x[l] <= x[r] + 3 and x[r] <= x[l] + 3
