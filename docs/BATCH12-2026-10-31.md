## 1. Design: run features, recorded in the IR

* **Run features, not file keys.** `PProblem.stutter` and `PProblem.prelanding` (`Trusted/Parse.lean`)
  are run features with default `true`; the parser no longer reads them. The keys `stutter` /
  `prelanding` are retired: removed from the two suite files (`lit_nahs25_salt_tank`,
  `lit_nahs25_engine_cooling`) and the three demos (`stutter_demo/salt_tank_stutter`,
  `prelanding_demo/{engine_cooling_prelanding,hold_reposition_strict}`), and removed from the
  unknown-key gate's list (`Trusted/KeyAudit.lean`), so a file that still carries one is refused
  (ERROR) rather than silently accepted as a no-op (the cleaner of the two options: a no-op key would
  still read as an opt-in).
* **Ablation switches.** `RELCERT_NO_STUTTER=1` (no stretch 0) and `RELCERT_NO_PRELANDING=1`
  (whole-domain right-only certificates, the `dynPre`/`dynPost` flags, as before 2026-10-30), read
  once per run by `Oracle.withRunFeatures` (`Trusted/OracleAPI.lean`), which sets the two fields at
  the start of `certifyWithData` and in `--emit-ir`. The emitted IR therefore records the run's
  values (`EmitIR` prints a field only when it is off, so the 50 suite IR literals are the files'
  parses; `relcert-test` ALL PASS).
* **CLI guards.** Unchanged in form, now on "the feature enabled in this run": a stretch-0 pairing
  with `p.stutter = false`, or a pre-landing node with `p.prelanding = false`, is an ERROR.
* **Kernel gates.** Unchanged in code, now reading the run's flags from the IR: `Emitted.timeOK`
  admits `lamN = 0` iff `IR.stutter`; `Emitted.plOK` admits a nonempty pre-landing record iff
  `IR.prelanding` (and then requires the emitted whole-domain flags off); `Emitted.nodeStage` (the
  node's region) is the pre-landing region iff `IR.prelanding`. Every suite IR records both as on
  (the default), so the bridge accepts stretch-0 pairings and pre-landing nodes; the kernel
  negatives (`scripts/stutter_kernel_checks.lean`, `scripts/prelanding_kernel_checks.lean`: the same
  records with the flag off fail `structOK` / `plOK`) still hold.
* **New theorem (wrapper, no new axiom, no `sorry`).** `Emitted.theorem3_keyed_of_records_pl`
  (`Proofs/Encoding/Emitted/Window.lean`): the mode-keyed records' theorem on the merged cover
  `withPL cov pl`, stated over the emitted cover behind `plOK`, the keyed twin of
  `theorem3_window_of_records_pl` (needed now that keyed benchmarks have pre-landing nodes). Pinned
  names are unchanged.

## 2. Generators and records

* `scripts/gen_v2_data.py`: every benchmark's run writes its pre-landing record
  (`BenchPrelanding/<b>.lean`, 50 leaves, empty for a cover without right-only nodes) and the
  aggregator `prelandTableV2` lists all 50; the ablation switches are removed from every run's
  environment; `--choice` regenerates the choice exhibits' cover-run leaves (cover, progress, choice,
  and the new `Choice/BenchPrelanding/<b>.lean`), checking that their IR and cut leaves are unchanged.
  The progress table now lists every benchmark: until now `lit_drl_lane_control` and
  `lit_freedm_meter` were left out of `progressTableV2`, so the bridge runner (`progV2`) sent their
  groups WITHOUT their progress certificates' queries, which their instances' `Verdicts` name (a
  pre-existing gap of the silent-pass kind, closed here; both now have right-only nodes).
* `scripts/gen_bridge.py`: an instance takes the pre-landing template when its record has nodes
  (window or keyed claim, `theorem3_keyed_of_records_pl` new), and `stutter_on` / `uses_stutter`
  when its cover has a stretch-0 pairing (read off the cover leaf, no longer off a file key).
* `scripts/gen_pack_rows.py` (new): derives the pack rows of `VerdictsV2/RunV2.lean` from the
  emitted leaves by the matrix's replay of the verified checker on the merged cover. Validated on
  the covers before this batch: 33 of the 38 benchmarks with modal rows reproduce the table exactly; the other five are
  extra hand rows the table lists (as recorded on 2026-10-29). Used for the two benchmarks whose
  joint pairings changed (`--joint watertank,watertank_twospeed`) and for the whole reposition
  table (`--dyn`).
* The reposition phase of `--check-quick-v2` (`runDynV2`): every reposition node is now a
  pre-landing node, so its rows carry `preland = true` and the runner sends each pack on the node's
  region read off the records exactly as the bridge does (`Emitted.dynRegionI` on the merged cover
  and the progress record; one group per component, its routes A/B/C as members). The record
  lookups `coverV2`, `coverV2M`, `progV2` moved from `RunBridge.lean` to `RunV2.lean`. The table is
  now every reposition pack the replay consumes over the suite (130 rows in 17 benchmarks; before,
  17 hand rows in 8 benchmarks, whole-domain).
* Demos: `gen_stutter_demo.py` (the salt tank demo now also has pre-landing nodes: pre-landing
  template), `gen_prelanding_demo.py` (the record comes from `emit_leaves`), `gen_strict_demo.py`
  (`watertank_strict` now has pre-landing nodes: the strict chain's
  `theorem3_window_strict_of_records_pl` over the merged cover); the three verdict scripts send the
  merged cover's groups.
