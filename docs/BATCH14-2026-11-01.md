## Phase A: the progress-certificate gap, fixed in the kernel (commit d9f0223)

**The gap.** The bridge merges each benchmark's pre-landing record into its cover
(`covM := withPL cov pl`) and decides `prog_ok : progOK IR n covM prog` in the kernel; `progOK`
requires `certOK` for every merged node. The tool's progress search (`OracleAPI.checkProgress`)
tries a helper stage in both directions (`for upY in [true, false]`) before a landing stage in
either direction, but `certOK` accepted one stage (either direction) or two upward stages only.
The stop-line friction and tyre rungs emit, for their right-BRAKE nodes, `[b >= 2 up, v <= 7/20
down]` (the brake builds up, then the speed falls to the stop threshold), so `decide` on
`prog_ok` would fail at build time (not unsound: a tool/kernel shape mismatch). The proper fix,
not the `RELCERT_NO_REPO` emission the scope suggested.

**Design.** The existing `phase_reg` (landing up, measure on any coordinate, stage invariant `Kf`)
and `phase_down_reg` (landing down, measure = the landing coordinate, no invariant) are the two
corners of a 2 x 2 grid (landing direction x measure). Rather than mirroring each missing corner,
two new phase lemmas take the stage's progress measure as a parameter: `g (x_z)`, a function of
one right coordinate that falls by `c` over every cycle that neither lands nor reaches `g <= 0`
(the premise `hmeas`). Everything else (landing at the start, landing on the line at the first
entry into the target, the self-loop's next cycle start, a non-self successor being a declared
unpruned exit) is the existing argument, copied. Three measure lemmas discharge `hmeas`.

| lemma (`Proofs/Encoding/Progress.lean`) | statement |
|---|---|
| `keep_preserved_down_reg` | a threshold crossed DOWNWARD stays crossed along a run in `Bf` when the field is `<= 0` at or above it (`boxle_thrLe_R`; the mirror of `keep_preserved_reg`) |
| `meas_up_reg` | a rising helper, not crossed at the cycle's end, rose by `r_h ε_R` (crossed within the cycle it would be kept, `keep_preserved_reg`; else `cycle_growth`) |
| `meas_down_reg` | the mirror for a falling helper (`keep_preserved_down_reg`, `cycle_decay`) |
| `meas_land_down_reg` | a falling landing coordinate that did not cross within the cycle fell by `r ε_R` (`cycle_decay`) |
| `phase_regM` | the cycles of one stage, landing upward, abstract measure |
| `phase_down_regM` | the cycles of one stage, landing downward, abstract measure, stage invariant `Kf` |
| `repoProgress_two_ud_reg` | helper up, landing down: stage 1 `phase_down_regM` with `meas_up_reg` (`Kf = ⊤`), stage 2 `phase_down_regM` under `Kf := θh <= x_h` (kept by `keep_preserved_reg`) with `meas_land_down_reg`, then `land_at_start_down` |
| `repoProgress_two_du_reg` | helper down, landing up: stage 1 `phase_regM` with `meas_down_reg`, stage 2 the existing `phase_reg` under `Kf := x_h <= θh` (kept by `keep_preserved_down_reg`), then `land_at_start` |
| `repoProgress_two_dd_reg` | both down: stage 1 `phase_down_regM` with `meas_down_reg`, stage 2 `phase_down_regM` under `x_h <= θh` with `meas_land_down_reg` |

All in the pre-landing region form (`Bf` = the region before the landing threshold, the node's
`dynRegion`), with the strict components on the closed region as before (the region is read off
the last stage only, so nothing changed there). Axioms: the closers at the three standard
axioms; the pins and the dispatcher with `z3_unsat_sound` (`scripts/progress_demo_verdicts.lean`).

Pins (`VerdictsV2/ProgressPin.lean`): `progressVerd_two_unpack` (any two-stage verdict: the
rebuilt region, field, guards and its five `unsat` queries; `stageQueries` was already

(`VerdictsV2/ProgressX.lean`). Kernel gate: `certOK` now calls `Progress.shapeOK` (one or two
stages, any directions; `Trusted/ProgressEmit.lean`); `certOK_shape` returns the stage list (its
two-stage disjunct no longer carries `sth.up ∧ st.up`). Dispatch: `Emitted.hrepoProg_of`
(`Emitted/Progress.lean`) and `hrepoProg_ofS` (`Emitted/StrictAnchor.lean`) case on the two
directions; two upward stages go to the unchanged `repoProgress_two_reg`. The keyed files reach the
closers through these two dispatchers and are unchanged. Every other existing name and statement
is unchanged.

**Tool.** No search change: `checkProgress` returns a found stage list only if it passes

emitted. Documented in `docs/PRELANDING.md` ("Two-stage certificates in every direction").
